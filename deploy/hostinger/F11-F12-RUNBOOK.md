# F11 → Chroma → F12 적용 안내

현재 단계: 로컬 구현·검증. 운영 적용은 미실행.

## 적용 전 필수 확인
- `f11-cpu.compose.yml`은 기존 KMovement의 두 외부 네트워크를 참조한다. 실제 이름과 Spring DNS를 다시 확인한다.
- 현재 로컬 검증 환경은 requirements-docker.txt의 고정 버전과 다르다. 운영 이미지 빌드와 동일 버전 재검증 전 배포 완료로 처리하지 않는다.
- CPU 이미지의 그래프/CSV 존재, /api/ready=200, 사용자 이력과 jobs 경로=404를 확인한다.
- web 런타임에 FASTAPI_URL=http://fastapi:8000, AUTH_BACKEND_URL=http://spring:8080과 서버 전용 KRIDE_INTERNAL_TOKEN을 제공한다. 브라우저 공개 변수에 토큰을 넣지 않는다. web의 Spring 접근 네트워크도 확인한다.
- CPU 서비스는 공개 포트를 열지 않는다. 기존 web·Spring 서비스를 재생성하거나 운영 DB를 변경하는 명령은 이번 작업에서 실행하지 않았다.

## F11
기존 Next 화면 /view/ROUTE_PLANNER의 길 찾기를 선택한다. 출발/도착 좌표, 동일 좌표, 도로에서 2km 밖, 왕복 거리, 날씨 대체 안내를 확인한다. 왕복은 같은 길로 돌아오는 거리 중심 방식이며 안전·관광 가중치로 코스를 선정하지 않는다. 시설 자료의 이름·분류가 비어 있으면 미등록으로 안내한다. 좌표 직접 입력 UI이며 주소 검색은 이번 구현에 포함하지 않는다.

## Chroma
현재 공개 /api/v1/tour/holy 응답 300건 모두 sourceUrl이 비어 있다. 확인된 공식 출처를 보완한 뒤 색인해야 한다. 링크를 추측해서 만들거나 이미지 출처를 장소 출처로 대체하지 않는다. 전체 DB 전수 조사 결과는 아니다.

전용 서비스 환경에서 `python -m scripts.index_public_pois`를 명시적으로 실행한다. CHROMA_MODE=persistent, CHROMA_PATH=/data/chroma, TORCHSERVE_ENABLED=false. 조회 요청은 색인을 변경하지 않는다. 검색 시 공개 목록을 다시 읽어 취소된 ID를 제외한다. 색인 재실행 시 오래된 ID도 삭제한다. 임베딩 모델과 E5 접두사 계약을 맞춘다. 다른 모델로 전환할 때 기존 컬렉션을 덮어 쓰지 말고 별도 경로/컬렉션으로 평가한다.

## F12
출처 있는 후보가 있을 때만 다음 단계로 진행한다. 서비스 토큰, 공급자 키, 실제 단가 두 값과 하루 달러 한도, 영속 비용 장부를 설정해야 한다. 기본값 0은 생성 차단이다. 사용자당 한국 날짜 기준 하루 10회, 전체 동시 생성 2회, 공급자 재시도 0회다. 실패한 예약액도 당일 한도에서 차감한다. 사용량 비용은 설정 단가로 계산한 추정치이다.

현재 고정 모델은 llama-3.3-70b-versatile이며 실제 공급자 가용성과 단가는 적용 시 공식 자료로 다시 확인한다. 이번에는 유료 공급자 호출을 실행하지 않았다. 예산 입력은 여행 지출 보장을 제공하지 않으며 AI 호출 비용 한도와 별개다. 추천은 공개 관광 장소 후보에 한정되고 영업시간·이동 가능성·여행 지출을 보증하지 않는다.

## 적용 후 확인과 되돌리기
길 찾기 5개 화면 폭, 실제 지도 선, 추천의 로그인/빈 후보/정상/한도/시간 초과와 마커·출처 일치를 확인한다. 동시 요청 부하와 컨테이너 최대 메모리는 별도 측정한다. 실패 시 web의 추가 연결 설정을 이전 배포 값으로 되돌리고 새 CPU 서비스만 중지한다. Chroma와 비용 장부 볼륨을 삭제하지 않는다. pgvector 설치나 운영 데이터 보정은 별도 범위다.
