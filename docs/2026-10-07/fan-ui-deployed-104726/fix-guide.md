# 팬 중심 UI · 수정·배포 결과
목표: 첫 화면에서 아티스트 사진·이름·저장 행동을 읽고 공식 소식으로 이어지게 한다.

1. 흰 카드에 남아 있던 흰 제목을 수정하고 상세 전용 사진+정보 배치를 적용했습니다.
2. 출처·라이선스를 기록한 실제 사진 33건과 팬을 향한 안내를 연결했습니다.
3. Hostinger 웹에 배포하고 운영 화면을 확인했습니다.

## 현재 위치
수정 → 자동 검증 → 이미지 발행 → 웹 교체 → 운영 화면 확인 완료. 이번 깊은 확인은 화면 첫인상과 탐색 동선입니다.

사진 미확보 15개 공개 항목에는 이름과 사진 준비 안내를 표시합니다. 역사적 자료 사진은 현재 멤버 활동·대표사진의 최종 선정이라는 뜻이 아닙니다. 출처 없는 소개·방문·최신 일정은 만들어 넣지 않았습니다.

이벤트는 해당 아티스트 ID로 좁히고 상품은 공개 근거 계약을 검사합니다. 상품 목록 연결은 출처·정품·실제 착용에 대한 새 보증이 아닙니다. 검색·관심 저장과 알림 구독은 별개입니다.

## 검증 한계와 관찰
이름 대비 16.27:1, 본문 대비 7.58:1 (운영 computed color / 흰 배경). 683px 검사는 좁은 화면 검사이며 실제 브라우저 200% 확대 검사를 대체하지 않습니다. Windows 로컬 미리보기는 기존 의존성 경로 문제로 실패했고 Linux 빌드 및 운영 브라우저 검증으로 확인했습니다. 첫 이미지 참조 검사는 실행용 이미지가 아닌 증명용 digest를 골라 사전 검사에서 중단됐으며 운영 변경 전 정확한 manifest digest로 수정했습니다.

## 배포 근거·복구
이미지: `ghcr.io/feed-mina/kmovement-web@sha256:981f9ac4bb150e25ba58db11fd72916b2d8ee3ea10ad0fb0d63092a01d80fc6b`. PR: https://github.com/feed-mina/KMovement/pull/277 . 빌드: https://github.com/feed-mina/KMovement/actions/runs/37558169040 .

main에 UI 코드를 병합하면 EC2 자동 배포가 함께 실행되는 구조라 코드 PR은 열린 상태로 보존하고 Hostinger에는 릴리스 브랜치 이미지를 배포했습니다. 문서만 두 저장소 main에 게시합니다.
