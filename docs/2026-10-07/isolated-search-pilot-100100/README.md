# 1,000개 격리 검색 파일럿 실행 및 운영 전환 판정

## 현재 작업 진행단계
파일럿 실행·결과 보존 완료. 운영 전환은 조건 미충족으로 보류했다. 사용자는 이번에 실행부터 운영 전환까지 요청했으며, 추가 승인 대기가 아니라 실제 품질·데이터 근거 조건의 미충족이다. 기존 v2와 준비 단계의 executionAllowed=false는 변경하지 않고 새 run-spec.json에 이번 실행 범위와 사용자 요청을 기록했다.

## easy-guide: 무엇을 확인했나
옛 DB를 수리하거나 운영 DB를 바꾼 작업이 아니다. 고정된 장소 1,000개만 별도 컨테이너에 읽기 전용으로 연결해 새 작은 검색 DB를 만들고 질문 120개를 A/B/C로 각각 검색했다. 기존 40,664개 전체 장소의 품질이나 역사적 모델을 증명하지 않는다.

A는 원문 문서·원문 질문, B는 A와 같은 저장 벡터·같은 컬렉션에 질문 앞 query: 만 추가, C는 문서 앞 passage: 를 붙여 별도로 임베딩한 비교다. A/B 저장 벡터 바이트 해시는 동일=True. 원문 공백·대소문자·Unicode는 바꾸지 않았다.

한국어·영어·일본어마다 양성 질문 30개(개발15/holdout15), 근거없음 질문10개(개발5/holdout5)다. 아래 표는 언어별 holdout 양성15개 기준이며 표본 규모가 작다. 정답은 이전 사용자 검수 기록이며 독립 외부 검수라고 주장하지 않는다. 질문·정답·기준은 이번 결과에 맞춰 고치지 않았다.

|---|---|---:|---:|---|---|

절대 기준은 Recall@5≥0.8, nDCG@10≥0.7이고, B/C는 각 지표 A 대비 감소≤0.02도 별도로 검사했다. 수치는 Chroma top10을 대상으로 계산했다. 정확검색 결과도 rows.json에 별도로 보존했다.

## 운영 전환이 아직 안 되는 이유
1. 후보 1,000개 모두 publicEligible=false다. 원본 이름·주소·좌표는 있지만 공개 출처 URL 필드는 없고, 원본 노드 해시가 공식 출처 URL을 대신하지 않는다. 좌표의 존재 역시 정확성 검증이 아니다. 가격·예산·아티스트 연결의 공식 증거가 없다.
2. 이번 runner는 검색 전용이다. 근거없음 질문도 검색했지만 답변 생성·거절 정책은 실행하지 않았다. unsupportedClaimAccepts와 positiveOverRefusalRate는 미측정이며 0이나 통과로 기재하지 않았다.
3. GitHub main의 현재 서비스 문서는 passage: 이름 | 주소 | 아티스트 형식이다. 이번 C의 여러 줄 name/address/category 형식과 다르다. 계약명 e5-prefix-v1만 붙여 통과시킬 수 없다.
4. 서비스 성능 목표, 로그인 후 실제 첫 응답, 취소·재시도, 일정·지도·출처 일치의 승인은 이 검색 파일럿으로 대체되지 않는다. 미통과 언어 지표가 있으면 그 조건도 해소해야 한다.

## 원인 분리: Chroma를 다시 수리하면 해결되는가
이번 새 DB의 ANN Recall@10은 A 0.9933 / B 0.9908 / C 0.9933으로 모두 0.99 기준을 통과했다. 양성 질문의 Recall@5·nDCG@10은 정확검색과 ANN에서 모두 동일했다. 따라서 이 표본의 영어·일본어 실패는 ANN 근사 검색만 조정해서 해결할 문제가 아니다. 옛 DB가 정상이라는 뜻도 아니다.
개발셋의 B 질문 “Find the location of Donggung Palace and Wolji Pond.”는 정답 “경주 동궁과 월지”를 top5에서 놓쳤고 정확검색도 놓쳤다. “Haeundae Beach”도 다른 해수욕장을 상위에 반환했다. 한국어 장소명과 외국어 표기를 연결하는 별칭·엔터티 매칭 보강을 조사할 근거다. 별칭 부재가 유일한 원인으로 증명된 것은 아니며, 새 모델이나 번역을 적용한 개선 실험은 아직 하지 않았다.
C 일본어는 Recall@5가 0.5333으로 늘었지만 nDCG@10은 0.4186으로 A보다 약0.0234 낮아 감소 한도0.02도 초과했다. passage: 접두사가 항상 개선한다고 판단할 수 없다. 한국어 통과 역시 이번 15개 holdout 결과이며 전국·모든 의도에 대한 보장이 아니다.

## fix-guide: 고정 실행본과 경계
- 실행 경로: /opt/kride-pilot-runs/20261007-100100. 전용 출력: results.tar.gz.
- 이미지: sha256:d29f48a31a8b408ed19272ca1e7b10ebae13b240a27e862d3d4217c528e2e0c3.
- 모델 revision: 614241f622f53c4eeff9890bdc4f31cfecc418b3.
- runner SHA256: 6498d7cd7b5a84dc3dfcc1e52bd7b90db34690bc04bc4cfb08ac8b7d7394b489.
- 실행 전 runtime/model/wheels 27,466개 파일과 압축본3개·입력5개 해시 재대조 통과. 입력 잠금은 run-spec.json 참조.
- CPU1, RAM4GiB, swap0, PID128, network none, 공개포트 없음, uid65532, cap-drop ALL, no-new-privileges, seccomp, read-only rootfs, 운영 DB/인증정보/socket 미마운트.
- /output256MiB·/tmp128MiB tmpfs. 검색 자식 최대1800초, 결과 회수 유예300초 후 PID1도 종료. 컨트롤러는 자원 부족 시 중단하고 정상 종료 후에도 컨테이너를 stop한다.
- 검색 전에 OS 제한 assertion 12개와 보존된 과거 정책의 false 값 확인 1개를 다시 통과했다. 과거 정책 확인은 현재 검색 실행이 비활성이라는 뜻이 아니며, 이번 실행은 새 run-spec의 executionAllowed=true에 근거했다. runner 정적 자체검토와 지표 픽스처 테스트를 통과했다. 독립 리뷰어가 검토했다고 주장하지 않는다.
- Chroma는 존재하지 않는 /output/new-chroma에만 생성했다. 기존 Chroma client나 운영 볼륨에 연결하지 않았다. 새 DB migration 목록·queue 행 수·색인 파일 목록은 chroma-lifecycle.json에 기록했다. 실패 시 그 실행에서 중단하도록 구현했다.
- 검색 자식이 종료된 후 살아 있는 컨테이너의 tmpfs를 tar 스트림으로 회수하고 로컬 SHA256을 대조했다. docker cp로 tmpfs를 복사하지 않았다. 보존용 압축본은 서비스 배포 파일이 아니다.

## ANN·시간·자원 판정
ANN Recall@10 vs 정확검색: {"A": 0.9933333333333334, "B": 0.9908333333333333, "C": 0.9933333333333334}. 기준0.99는 의미 정답 정확도와 별개다. exact는 점수 내림차순·ID 오름차순, ANN 반환 top10 동률은 거리·ID 순이다. 경계 동률에서는 서로 다른 ID가 같은 점수를 가질 수 있으므로 원시 결과를 보존한다.

총 runner 시간 91.75초, 모델 로드 6.55초, 프로세스 peak RSS 1062.1MiB, 출력 파일 합계 9,385,353바이트. 단일 프로세스 RSS와 전체 컨테이너 메모리는 다른 값이며 after.json에 cgroup 기반 docker stats 표본을 보존했다.
질문 임베딩+ANN 검색 지연(ms): {"A": {"firstQueryMs": 29.990050476044416, "warmP50Ms": 31.259202864021063, "warmP95Ms": 41.659595072269425}, "B": {"firstQueryMs": 28.30559480935335, "warmP50Ms": 31.429752707481384, "warmP95Ms": 36.643107049167156}, "C": {"firstQueryMs": 30.224301852285862, "warmP50Ms": 32.99023909494281, "warmP95Ms": 47.128324676305056}}.
모델이 이미 로드된 상태에서 변형별 첫 질문과 나머지119개 p50/p95다. cold p50/p95 분포는 측정하지 않았다. 모델 로드 시간 하나를 cold p95로 부르지 않는다. 서비스 SLA 통과 판정은 없다. truncation ID 수=0.

## 전후·보존
이전: 실행본 준비와 모델 로드만 완료, 검색 미실행.
현재: 1,000개 새 격리 DB·120문항×3조건 검색과 근거 보존 완료. 운영 전환 미실행, 전량 재색인 미실행.
기존 운영 컨테이너 상태 동일=True; 시작시각/재시작횟수/상태/헬스 비교다. 로그인 기능 검증이나 장기 부하 보장을 뜻하지 않는다. 원본·운영 설정·볼륨과 이전 보고서는 보존했다. 동일 호스트의 CPU·메모리·디스크 I/O 공유 한계는 남는다.

## 다음 해결 순서
개발 질문의 실패 원인을 분류해 다국어 장소명 표기·별칭 근거를 준비하고, 새 정답 검수와 새 holdout을 고정한 후 변경본을 평가한다. 이번 holdout을 보면서 프롬프트나 임계값을 조정해 같은 시험을 통과시키지 않는다.
공식 출처 URL·좌표·지역·가격·아티스트 증거를 항목별로 연결한 별도 공개 후보 목록을 만든다. 근거없는 조건은 명시적으로 미지원/미확인 처리하고 양성 과거절도 함께 평가한다.
검색·출처 계약·응답거절·성능·로그인 수용 검사를 통과한 버전만 별도 컬렉션과 정확한 image digest로 전환하고 이전 release/collection을 rollback 대상으로 유지한다. 현재 증거로 1,000개를 운영에 연결하는 것은 부적합하다.
