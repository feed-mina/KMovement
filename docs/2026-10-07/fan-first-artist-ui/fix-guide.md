# 팬이 머무르고 싶은 아티스트 페이지

목표: PC 첫 화면에서 아티스트를 알아보고, 마음에 드는 정보를 저장하고, 확인된 일정·장소로 자연스럽게 이어지는 화면을 설계한다.

## 현재 단계 · 분석 완료 / 구현·배포 미실행
사진·이름·짧은 소개·저장 버튼을 먼저 보여주는 아티스트 상세를 제안한다.
이번 심층 범위는 ‘아티스트 상세의 첫인상’이며 목록·일정·상품·마이는 연결 계약만 정리한다.
운영 UI의 실제 클릭·computed style은 확인하지 못했다. 제공 캡처, 로컬 코드, 공개 API와 이미지 응답을 근거로 분석했다.

## P0/P1/P2 수정 명세
P0: 읽을 수 있는 이름과 소개. 흰 카드 제목 #172033·본문 #475569 제안. 일반 텍스트 4.5:1, 큰 텍스트 3:1 이상 확인. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). 이 수치는 실제 화면 측정치가 아니라 검증 기준이다.
P1: 상세 전용 사진+정보 2열. PC 최대폭1200px, 사진 약42%·텍스트58%, 바깥 여백24–40px, 상단 시각영역360–420px를 시안 시작값으로 제안한다. 큰 화면을 빈 박스로 채우지 않는다. 900px 미만 1열로 전환하고 200% 확대에서 잘림 여부로 수치를 조정한다.
P1: 이름을 실제 h1으로 승격. ‘아티스트 상세 → 상세 정보 → ARTIST’의 반복 제목을 줄이고 목록 복귀를 작은 breadcrumb로 둔다. 사진 위 글자 덮기는 기본으로 쓰지 않는다.
P1: 사진은 승인된 실제 그룹 사진을 쓴다. 현재 BTS 파일은 가로로 긴 행사 사진이므로 존재만으로 대표사진 최종 채택하지 않는다. 새 대표사진의 출처·사용 범위·크롭 초점을 기록한다. 전원 얼굴이 잘리는 crop은 피하고 필요하면 contain을 사용한다. AI 생성 얼굴은 실제 아티스트 사진의 대체재로 쓰지 않는다.
P1: ‘내 아티스트로 저장’과 ‘공식 소식 보기’를 우선 행동으로 둔다. 이벤트·상품 버튼은 artistId/slug 필터와 돌아오기 문맥을 유지한다. API가 필터를 지원하는지 별도 확인한다. 알림을 구현하지 않았으면 ‘알림 받기’를 제공하지 않는다.
P2: 일관된 카드·칩·간격·선택 상태를 목록과 마이에 확장. KpopCards 공유 CSS 변경은 이벤트 카드·상품 화면까지 회귀 확인한다.

## 팬 관점 문구 설계
현재: ‘월드투어와 팝업이 자주 열려 서울 도심 동선과 함께 계획하기 좋은 그룹입니다.’ 팬에게 아티스트를 여행 효율로 설명하고, 최신 일정으로 오해할 수 있다.
제안 헤드라인: ‘좋아하는 마음이, 다음 추억으로.’ 감성 문장과 사실 설명을 분리한다.
제안 서비스 소개: ‘BTS의 공식 소식에서 다음에 함께하고 싶은 순간을 찾아보세요. 마음에 드는 일정과 장소는 내 목록에 차곡차곡 담아요.’ 실제 저장·일정 기능 범위에 맞춰 최종 검수한다. 여행 방문 사실이나 신규 공연 존재를 약속하지 않는다.
정체성 소개: 공식 아티스트 소개에서 확인한 사실 1–2문장 + 출처·검수일. 이번에는 확인하지 않은 수상·활동·팬덤명·현재 멤버 활동을 채워 넣지 않는다. 팬덤 호칭도 아티스트별 검수 후 사용한다.
일정 없음: ‘아직 확인된 새 일정이 없어요. 공식 채널에서 다음 소식을 만나보세요.’
조회 오류: ‘소식을 불러오지 못했어요. 잠시 후 다시 시도해 주세요.’ 데이터 없음과 장애를 분리한다.
장소 관계: ‘공식 콘텐츠에서 확인한 장소’, ‘팬이 제안한 장소’, ‘공연장 주변 편의 장소’를 구분한다. 근거 없는 ‘멤버 단골·방문 인증’을 만들지 않는다. 비공개 동선·숙소·공항 이동을 팬 여행 콘텐츠로 유도하지 않는다.
공식 링크의 사실 확인과 사진 사용 권한은 별개다. 비교 서비스의 팬 전용 이미지를 무단으로 가져오는 것을 사진 확보 방법으로 제안하지 않는다.

## 사용자와 도우미의 다음 행동
