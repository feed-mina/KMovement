# 작은 공개 목록으로 시작하는 다국어 코스·챗봇

목표: 근거가 검토된 서울 장소로 코스를 만들고, 코스 아래에서 한국어·영어·일본어로 같은 장소·지도·출처에 관해 대화한다.

1. 1,000개 파일럿은 실행됐지만 영어·일본어 검색과 공개 출처 조건을 통과하지 못했다.
2. 장소를 20개로 줄이는 안을 제안한다. 필수 증거를 빼는 대신 지원 지역·조건을 줄인다.
3. 개발 개선 → 새 독립 정답·시험 고정 → 서비스 검사 → 통과 버전만 전환한다. 이번 결과물은 분석·명세이며 실행 결과가 아니다.

## 현재 위치와 다음 행동
전체 목표 → ① 공개 범위·근거 준비 / ② 다국어 검색 / ③ 코스와 대화 연결 / ④ 검증·전환. 이번에는 **① 공개 범위·근거 준비**를 깊게 확인했다. 나머지는 실행 순서와 통과 조건을 명세했다.

다음 행동 하나: 서울 20개 후보의 항목별 출처 표를 작성하고, 검수 전 후보를 공개 목록과 분리한다. 이번에 확보한 것은 공식 표기 근거 탐색 2건이며, **새 목록의 완전 검수 완료는 0건**이다. 20개 확보·새 정답 검수·새 holdout 고정·실험·코드 수정·운영 전환은 아직 하지 않았다.

가설: 검토된 다국어 명칭과 별칭을 추가하면 다른 장소가 검색되는 현상이 줄어든다. 검증: 개발 질문으로 원인을 나눠 비교한 뒤 설정을 동결하고, 새로운 독립 holdout을 한 번 평가한다. 현재는 **미확인 가설**이다.

## 1. 줄일 수 있는 것 / 유지할 것

| 항목 | 제안 | 줄이면 안 되는 이유 |
|---|---|---|
| 공개 후보 | 1,000개 일괄 연결 대신 서울 20개 목표. 가까운 권역에서 3~4곳 코스를 만들 수 있도록 사전 선정 | 실패한 질문을 제외해서 20개를 고르면 시험 회피가 된다. 선정 기준·제외 사유를 평가 전에 고정 |
| 지역·일정 | 서울·당일치기 | 영어·일본어 지원은 해외 여행 지원과 다르다. 서울+경기를 조용히 서울로 바꾸지 않음 |
| 출처 URL 수 | 한 공식 문서가 여러 항목을 뒷받침하면 재사용 가능 | URL 개수보다 각 주장과 근거 구간의 연결·유효성이 중요 |
| 가격·아티스트 조건 | 검증한 값만 제공. 없으면 미확인/미지원 | 모르는 가격을 0원으로, 일반 장소를 팬 성지로 바꾸지 않음 |
| 새 시험 | 새 holdout 120문항 유지 제안 | 후보를 줄여도 3개 언어·정답이 없는 질문·과거절 검사는 유지 |
| 기존 운영 | 원본·기존 컬렉션 보존 | 새 목록이 과거 40,664개 데이터나 1,000개 품질을 대표하지 않음 |

20개는 확정된 적격 개수가 아니라 **시작 범위 제안**이다. 출처 검수 후 부족하면 부족 사실을 보고하고 범위 명세를 다시 고정한다. 시험 결과를 본 뒤 후보·조건을 빼서 같은 시험을 통과시키지 않는다.

## 2. 기존 파일럿에서 확인한 실패
[기준 보고서와 결과](https://github.com/feed-mina/KMovement/tree/main/docs/2026-10-07/isolated-search-pilot-100100)의 보존 기록을 확인했다. 결과 시점은 2026-10-07 파일럿이며 현재 서비스의 실시간 측정이 아니다.

| 실험 | 한국어 R@5 / nDCG@10 | 영어 | 일본어 |
|---|---|---|---|
| A 원문 문서·원문 질문 | 1.000 / 1.000 | 0.400 / 0.367 | 0.467 / 0.442 |
| B A와 같은 벡터·질문 접두사만 변경 | 1.000 / 1.000 | 0.400 / 0.407 | 0.467 / 0.457 |
| C 별도 문서 형식·별도 벡터 | 1.000 / 1.000 | 0.400 / 0.400 | 0.533 / 0.419 |

각 언어 holdout 양성 15개 결과다. C는 B와 같은 벡터가 아니다. exact 검색과 ANN의 양성 검색 지표가 같았으므로 이 표본에서는 근사 검색 설정만 바꿔 해결됐다고 볼 근거가 없다. ANN Recall@10은 A 0.9933 / B 0.9908 / C 0.9933으로 통과했지만 의미 검색은 별도 실패했다.

공개 적격은 **0/1,000개**였다. 좌표 필드가 있다는 사실은 좌표 검수 증거가 아니다. 원본 노드의 해시는 공식 장소 출처 URL을 대신하지 않는다. 가격·아티스트 연결도 별도 근거가 필요하다. 응답 거절·양성 과거절·로그인 수용은 검색 전용 runner에서 측정하지 않았다.

## 3. 공식 표기 근거와 별도 공개 후보 계약

| 준비 항목 | 확인한 공식 자료 | 이번 상태 |
|---|---|---|
| 창덕궁과 후원 | [한국관광공사 영어](https://english.visitkorea.or.kr/svc/whereToGo/locIntrdn/rgnContentsView.do?menuSn=351&vcontsId=94399)의 Changdeokgung Palace Complex / [일본어](https://japanese.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=111042)의 昌徳宮と後苑 | 한국어 병기와 언어별 표기 근거를 확보. 궁궐과 후원의 입장·예약 범위가 달라 동일 상품처럼 합치면 안 됨 |
| 서울역사박물관 | [박물관 일본어 소개](https://museum.seoul.go.kr/jpn/jpn-introduction/jpn-mission.jsp)의 ソウル歴史博物館 | 일본어 표기 근거 확보. 영문명·좌표·조건별 요금까지 완료한 후보라는 뜻은 아님 |

조회일 2026-10-07. 위 자료는 별칭 검토의 시작점이다. 검토자 승인·좌표 확인·가격 적용 조건·아티스트 관계 확인까지 완료했다고 표시하지 않는다. 자동 번역명·로마자 음역은 공식명과 구분하고 출처 없는 별칭을 정답으로 승격하지 않는다.

공개 후보는 기존 벡터 목록과 별도 관리한다. 제안 필드:

| 필드 | 근거·검증 | 없을 때 |
|---|---|---|
| poiId / canonicalName / names.ko,en,ja | 안정 ID, 원문 그대로 보존, 언어별 출처·검토자·검토일 | 언어별 미검수 표시. 초기 3개 언어 공개 후보는 필수 표기 검수 전 제외 |
| aliases[] | alias, locale, official/transliteration, URL, 근거 구간, 동일 개체 판정 | 생성 모델이 만든 이름을 공식 별칭으로 등록하지 않음 |
| coordinates / region | 공식 좌표 또는 공식 주소와 신뢰 가능한 지도 자료의 교차 검증; 방법·오차·주소 일치 기록 | 코스·지도 후보에서 제외. 지역은 코드와 사람이 보는 이름을 함께 저장 |
| priceEvidence | 통화·대상·날짜·입장권 종류·포함/제외 비용·공식 URL·검수일 | unknown. 무료 추정 금지. 전체 예산 충족 주장 미지원 |
| artistEvidence | artistId, 관계 종류, 장소 ID, 공식 문장/공식 자료 URL, 날짜·유효기간 | unknown. 관련 없음으로 단정하지 않으며 아티스트 조건 충족으로 선택하지 않음 |
| visitConstraints | 휴관·예약·운영시간의 출처·기간 | 예약 가능/영업 중이라고 단정하지 않음. 시간표 확정이 필요하면 해당 후보 제외 |
| eligibility / capabilities | source-verified, course-eligible, price-eligible, artist-eligible를 분리 | 계약 이름을 붙이는 것만으로 기존 guard 통과시키지 않음 |

각 항목은 value / status(verified, unknown, unsupported, expired) / sourceUrl / sourceExcerpt 또는 위치 / retrievedAt / contentHash / reviewedBy / validUntil을 연결한다. 본문 해시는 수집 당시 근거 보존용이며 사이트가 현재도 같은 내용을 보증한다는 뜻이 아니다. 전체 저작물을 무단으로 보고서에 복제하지 않는다.

**필수 장소 근거**는 URL·동일 장소·좌표·지역·다국어 이름이다. 가격/아티스트는 빈칸으로 감추지 않고 상태를 기록한다. 사용자 요청이 가격 보장/아티스트 연관을 필수로 요구하면 해당 증거가 있는 후보만 적격이다. 부족하면 지원 불가를 설명하고 일반 코스로 바꿀지 선택받는다. 일반 장소 목록을 팬 맞춤 코스로 광고하지 않는다.

## 4. 다국어 검색과 새 시험 고정

1. 기존 실패에서 개발 질문만 사용한다. 제안 개발 세트 60개: 각 언어 양성 15 + 근거 없음 5. 유사 이름·지역 충돌·지점·복합 장소·혼합 문자를 포함한다.
2. 원문·공백·대소문자는 보존한다. 검색용 Unicode 정규화/띄어쓰기/대소문자 처리와 이름 exact-match·별칭 우선·벡터 보조 규칙은 별도 버전으로 기록한다. 별칭 인식만으로 증거가 없는 조건을 충족시킬 수 없다.
3. 저장 문서와 질문 형식을 각각 고정한다. 보존된 서비스 스냅샷은 `passage: 이름 | 주소 | 아티스트`, 질문은 `query: 질문`이었다. 파일럿 C의 다중 행 이름/주소/분류 형식과 다르다. 실제 적용 formatter의 바이트와 해시로 동등성을 검사한다.
4. A/B는 같은 컬렉션·저장 벡터 해시에서 질문 접두사만 바꾼다. 별칭 문서 추가·C 형식 변경은 독립 실험이다. 표시 번역, 검색 문서 변경, 질문 형식을 동시에 바꿔 효과를 혼동하지 않는다.
5. 개발 작업이 끝나면 후보 목록·별칭·문서/질문 형식·검색/거절 임계값·프롬프트·생성 모델 ID/공급자·임베딩 revision·tokenizer/config·라이브러리 해시를 고정한다. 공급자가 고정 revision을 제공하지 않으면 모델 alias 변동 위험을 기록하고 변경 시 수용 검사한다.
6. 변경 작성자와 분리된 언어 검수자가 새 정답 ID·허용 대체 ID·관련성 등급·거절 이유를 검토한다. 두 검토자의 불일치는 조정 기록으로 남긴다. **독립 검수자와 정답은 아직 확보되지 않았다.**
7. 새 holdout 120개: 언어별 양성 30 + 근거 없음 10. 번역·바꿔 말한 동일 질문은 intent/장소 묶음으로 나눠 개발 세트와 누출을 막는다. 같은 공개 장소를 물을 수 있어도 같은 질문 템플릿의 번역을 양쪽에 나누지 않는다. 20개 목록의 지원 범위만 평가하며 미관측 장소 일반화는 주장하지 않는다.
8. holdout은 분리된 평가 담당이 보관하고 hash·접근 이력·잠금 시점을 남긴다. 평가 전에 개발 코드/threshold/prompt와 baseline을 동결한다. 보고서 본문에 holdout 문제·정답을 싣지 않는다.
9. 한 번 결과를 본 뒤 변경이 필요하면 그 시험은 회귀 자료로 전환하고 다음 버전은 새 독립 holdout으로 검증한다. 재시도·모델 선택·가장 좋은 시드 선택을 같은 holdout에서 반복하지 않는다.

기존 1,000개 지표와 새 20개 지표를 같은 난이도로 비교하지 않는다. **같은 20개와 동일 새 질문에 대한 동결 baseline**을 준비한다. 20개 중 top5는 쉬워질 수 있으므로 비슷한 이름의 오답 후보·최종 선택 ID 정확도·잘못된 장소 확정 건수를 함께 공개한다. 기존 1,000개 전체 성능 개선을 주장하지 않는다.

| lib/types/krideChat.ts | message/intent/지역/기간/예산, 명시적 응답 언어·일정 revision 없음 | responseLocale=ko/en/ja, itineraryId/revision, requestId 명세 추가 |
| components/DynamicEngine/hook/useKrideItinerary.ts | 시간 제한·사용자 재시도·연속 오류 제한 | API capabilities를 선택 화면과 맞추고 중복 요청/청구 방지 유지 |
| remote-public_search.py (보존 스냅샷 99,111행) | 문서와 질문에 서로 다른 접두사 | canonical 이름/별칭 해석층과 evidence-aware 검색. 실제 코드 위치는 구현 전 현행 재확인 |
| remote-public_itinerary.py (보존 스냅샷) | 서울·당일치기 guard, ground_plan이 공식 후보 ID로 이름·좌표 재구성 | 같은 후보 버전으로 일정·지도·챗봇 답변을 묶고 locale은 표시만 변경 |

공통 흐름: 로그인 → 지원 조건 안내 → 코스 생성 → 서버가 소유권을 확인한 일정 ID·revision 저장 → 일정/지도/출처 표시 → **같은 화면 아래 ‘이 코스에 질문하기’** → 선택 언어로 답변. 별도 영어/일본어 학습 채팅 메뉴를 이 기능의 완료 증거로 대체하지 않는다.

서버는 브라우저가 보낸 장소/가격/사용자 ID를 그대로 신뢰하지 않고 인증 사용자와 현재 공개 목록으로 다시 조회한다. 지도 마커·일정 카드·답변 출처는 동일 poiId를 사용한다. 언어만 바꾸면 장소 ID와 좌표는 유지된다. ‘두 번째 장소’는 현재 일정 순서로 해석한다. 일정 버전이 달라지면 갱신을 안내한다.

질문은 조회와 코스 변경을 구분한다. 설명 요청은 일정을 바꾸지 않는다. 장소 교체는 변경안을 보여준 뒤 반영하며 확인한 최신 출처·시간 조건을 다시 검사한다. 이름이 모호하면 지점/지역을 묻는다. URL·좌표·가격은 모델 자유 생성 값을 쓰지 않는다.

## 6. 독립 통과 기준 — 아래 숫자는 실행 전 확정할 제안값

| 검사 | 제안 통과 기준 | 실패 시 |
|---|---|---|
| 검색 | 언어별 R@5≥0.80, nDCG@10≥0.70; 같은 범위 baseline 대비 하락≤0.02. 최종 잘못된 장소 확정 0건/검사 건수 병기 | 개발 수정 후 새 holdout. 기존 시험 통과 목적 재조정 금지 |
| ANN | ANN 사용 시 exact 대비 Recall@10≥0.99 | 튜닝은 개발 세트에서만. 소규모 exact 선택 시 별도 설계로 고정, ANN 미적용을 통과로 가장하지 않음 |
| 출처 계약 | 공개 필수 필드 100% 검수, 조건별 eligibility 검사, 폐기/기한 만료 후보 제외 | 적격 후보 제외 후 새 범위 버전. guard 우회 금지 |
| 거절·과거절 | 근거 없는 주장 수락 0/검사수; 언어별 양성 과거절≤5% (30개이면 최대 1개). 부분 지원 질문도 검토 | blanket refusal로 안전 수치만 얻지 않음. 모델 오류와 근거 부족을 구분 |
| 응답 품질 | 원하는 언어·일정 문맥·출처 연결 전부 일치. 근거 없는 가격/아티스트/예약 가능 확정 0건 | 언어별 독립 검토 결과·분모 기록 |
| 성능 | 사전 제안: 첫 의미 있는 응답 p95≤10초, 코스 완료 p95≤30초, 동시 2건. cold10/warm30 구분 | 개발 측정으로 목표 확정 후 본 시험. 수용 실패를 120초 타임아웃 안에 끝났다는 이유로 통과 처리 금지 |
| 로그인·수명주기 | 실제 로그인, 언어 3종, 일정/지도/출처 ID 일치, 종료·중단·재시도·로그아웃·계정 전환, 429/공급자 오류 구분 | HTTP200·컨테이너 healthy만으로 완료 판정 금지 |

표본이 작으므로 관측 0건은 모집단 위험 0을 의미하지 않는다. 언어별 분모와 신뢰구간/불확실성을 함께 보고한다. cold10/warm30 p95는 작은 표본의 관측값이며 운영 SLA 보증이 아니다. 기존 36~47ms warm p95는 **검색/임베딩만**이며 로그인·네트워크·생성 모델을 포함한 첫 응답 시간이 아니다.

기존 비용 조건: 합산 하루 최대 1달러·사용자당 10회·동시 2건 유지. 새 120개 검색 질문은 격리 검색 검사이며 생성 모델 검사를 대신하지 않는다. 실제 답변·성능·로그인 생성 요청도 한도 안에서 여러 날 나눠 수행한다. 시험이라고 제한을 해제하지 않는다. 전부 검사하지 못하면 미완료로 남긴다. 첫 응답은 단순 연결 ACK가 아닌 첫 유효 토큰/내용으로 측정하고, 콜드 로드·취소 후 슬롯 반환·중복 청구도 기록한다.

## 7. 전환과 되돌리기

개발 검증 → 새 정답 검수/holdout 동결 → 격리 전체 검사 → 테스트 계정 수용 → all-pass → 별도 컬렉션과 정확한 이미지 digest로 전환. 실패 분기 → 현재 release 유지 → 실패 항목만 개발 수정 → 새 버전 검증.

배포 묶음은 web/Spring/CPU 각각의 source SHA와 image digest, Chroma 이미지/클라이언트 버전, 컬렉션 ID, 후보·별칭·문서·정답·시험 hash, 임베딩 revision, 생성 모델 ID, prompt/schema/capability 버전, 이전 release/collection을 포함한다. 현행 배포 digest를 이번에 확인하지 않았으므로 예전 파일럿 digest를 운영 대상으로 재사용하지 않는다. `latest` 태그만으로 전환하지 않는다.

새 컬렉션은 독립 경로에서 만들고 원본·운영 볼륨·운영 인증정보·Docker socket을 연결하지 않는다. 기존 제한 컨테이너에서도 호스트 여유 자원·해시·mount·network·CPU/RAM/PID·시간 제한을 실행 직전 재검사한다. 같은 호스트의 부하 영향은 남는다.

동일 버전 조합을 원자적으로 참조하게 하고, 불일치 시 요청을 막는다. 이전 이미지·컬렉션·환경 설정을 유지한다. 테스트 계정에서 먼저 확인하고, 5xx/출처 불일치/언어 오류/비용 제한 위반/허용 지연 초과가 나타나면 이전 조합으로 되돌린다. rollback smoke test와 데이터 스키마 호환성을 미리 확인한다. 오래된 컬렉션 삭제·원본 수리·전량 재색인은 이 안에 없다.

현재 전환을 막는 것은 자동 승인 거절이 아니라 **미충족 증거 조건**이다. 이전 1,000개는 지금 운영에 연결하지 않는다. 이번 요청에 대한 산출물은 배포까지 가는 보고서이며, 실제 코드·검색·운영 변경은 수행하지 않았다.

## 8. 역할·요청문·완료 증거
사용자가 지금 터미널에서 할 일은 없다. 독립 언어 검토는 실제 검토자 확보가 필요하며 동일 작성자의 자기 검토를 독립 검수라고 부르지 않는다.

다음 준비 요청문: “서울·당일치기 공개 후보 20개를 목표로 한국어·영어·일본어 표기와 URL·좌표·지역·가격·아티스트 관계를 항목별로 연결해줘. 미확인은 명시하고, 개발 실패 분류만으로 별칭·문서 계약을 준비해줘. 독립 정답 검수와 새 holdout은 분리하고 접근 이력·hash를 남겨줘. 현재 원본·운영은 보존하고 이번에는 새 목록과 실행 전 고정 명세를 보여줘.”

완료 증거: 후보별 검수표와 제외 사유, 언어 검토·불일치 조정 기록, 동결 manifest와 hash, baseline/변경본 언어별 평가와 분모, 근거 없는 주장·과거절 판정, 실제 로그인 화면/지도/답변/출처 일치 기록, 응답 시간·종료/재시도·비용 기록, release와 rollback manifest. 실패 항목이 있으면 그 상태와 다음 개발 검사를 함께 제출한다.
