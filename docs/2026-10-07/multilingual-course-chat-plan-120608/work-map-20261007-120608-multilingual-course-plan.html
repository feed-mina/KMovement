다국어 코스·챗봇 진행 지도

목표: 출처가 검토된 서울 코스를 생성하고 같은 화면에서 세 언어로 질문한다.

  1. 기존 1,000개·120문항 결과를 확인했고 영어·일본어와 공개 출처 gate 실패를 구분했다.
  2. 서울 20개·3개 언어의 작은 공개 범위와 새 시험·응답·배포 계약을 제안했다.
  3. 이번에는 보고서만 작성했다. 후보 완전 검수·독립 정답 검수·새 holdout 고정·코드 수정·검색 실행·배포는 미실행이다.

현재 상태

분석 완료 → 공식 명칭 근거 탐색 2건 → 새 완전 검수 후보 0건 → 목표 20건 준비 예정 → 새 시험 120문항 제안 → 통과할 때만 운영 전환.

검증을 분리한다

검색 통과 ≠ 공개 출처 통과 ≠ 응답 거절 통과 ≠ 성능 통과 ≠ 실제 로그인 수용 통과. 기존 warm 검색 수십 ms는 전체 첫 응답 시간이 아니다. 기존 공개 적격 0/1,000은 이름 번역만으로 바뀌지 않는다.

다음 작업

서울 20개 후보를 별도 공개 목록으로 검수한다. URL 수는 중복을 줄일 수 있지만 각 주장에 대한 근거 연결은 유지한다. 20개를 선정할 때 개발/시험 성적을 보고 불리한 장소만 빼지 않는다. 원본과 기존 운영 컬렉션은 보존한다.

진행과 실패 분기

공개 범위·출처 준비 → 개발 질문 개선 → 독립 정답 검수와 새 시험 동결 → 격리 평가 → 실제 로그인 수용 → 통과 조합 전환. 어느 단계에서든 실패하면 현재 운영을 유지하고 개발로 돌아간다. 시험을 본 뒤 변경하면 다음 버전에는 새 시험이 필요하다.

인계

쉬운판은 사용자 행동과 화면, 상세판은 후보 계약·실패 분류·파일·측정 기준·전환과 복구를 설명한다. 별도 source registry 초안은 표기 근거 탐색 2건이며 공개 적격 목록이 아니다. 코드나 운영 설정을 바꾸지 않았다.
