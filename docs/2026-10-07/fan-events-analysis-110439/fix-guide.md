# 팬 일정 · UI 벤치마킹과 수정 명세
목표: 좋아하는 아티스트의 일정을 국내·해외·온라인으로 골라, 날짜와 장소를 한눈에 이해한다.

1. 현재 운영 화면을 PC 1440×1000·모바일390×844로 새로 캡처했습니다.
2. 관심 아티스트와 개최 구분을 먼저 고르는 예상 GUI를 만들었습니다.
3. 이번은 조사·시안 검증 단계이며 제품 코드·운영 데이터·배포는 변경하지 않았습니다.

## 현재 위치와 결론
전체 목표 → 일정 탐색 → **관심 아티스트 × 개최 구분**을 깊게 검토했습니다. 월간 달력·알림·캘린더 내보내기는 후순위입니다.
가설: 날짜 입력보다 ‘누구의 일정인가’와 ‘어디서 열리는가’를 먼저 고르면 팬이 원하는 일정을 더 쉽게 찾는다.
검증: 현재 DOM·공개 API·코드·공식 서비스 문서 비교와 독립 시안 필터 동작을 확인. 실제 팬의 탐색 시간·만족도 개선은 아직 미검증입니다.

## 확인된 현재 상태 · 2026-10-07
- 운영 `/view/KPOP_EVENTS`에서 긴 날짜 설명과 시작일·종료일·자유입력 지역이 먼저 보입니다. 관심 아티스트 선택·국내/해외 탭은 없습니다. PC 첫 화면의 핵심은 검색 규칙이며 실제 일정은 아래로 밀립니다.
- 공개 `/api/v1/kpop/events` GET 응답은 HTTP200, 현재 이후 90건·16개 아티스트입니다. 이는 전체 DB 개수가 아닙니다. 응답 시점의 기본 조회 범위입니다.
- 지역 문자열 29종에는 서울·경기(합계3건), 온라인(4건), 일본·미국 등 나머지 국가/지역 문자열(83건)이 섞였습니다. **이 분포는 원문 문자열 집계이지 검증된 국내/해외 분류 결과가 아닙니다.** ‘서울이 아니면 해외’로 처리하면 안 됩니다.
- 응답에 artistId·artistNameKo·date·region·venue·officialUrl·followed가 있습니다. countryCode·도시 별도 필드·개최 시간대·공연 시작/종료 시각·확인 시각·취소/연기 상태는 이 공개 응답에서 확인되지 않습니다.
- 90건 모두 officialUrl 값은 있으나 URL 존재가 최신 일정·개최 국가·공식성 재검증 통과를 뜻하지 않습니다. 이번에는 각 공지 내용까지 재검수하지 않았습니다.

## 권장 화면과 우선순위
**P1 · 첫 화면:** ‘좋아하는 아티스트와 다음에 만날 순간’ 아래 대상(내/전체 아티스트) → 사진과 이름 선택 → 개최 구분 → 날짜순 목록. 긴 규칙은 ‘날짜 안내’에 접되 시간 미정·취소처럼 결정을 바꾸는 정보는 카드에 남깁니다.
**P1 · 기본값:** 로그인+관심 저장 있음은 ‘내 아티스트’, 비로그인은 ‘전체 아티스트’. 직접 고른 아티스트는 비로그인도 공개 탐색 가능. 저장 없음과 아직 로그인하지 않음을 구분하고 전체 추천으로 조용히 바꾸지 않습니다.
**P0 · 개최 분류 정확성:** 국내는 대한민국 개최. 검수된 countryCode=KR로 판단. 온라인은 별도, 위치 미확인은 별도 안내. 국가/지역 드롭다운은 해외 선택 때 열립니다. 사용자 위치를 자동 수집할 필요가 없습니다.
**P0 · 해외 날짜:** 출처의 개최지 날짜와 IANA 시간대를 확인하고, 시간이 있는 경우에만 한국 시간을 보조 표시. date-only를 자정 시각으로 꾸며 변환하지 않습니다. 기존 event_date가 현지 날짜인지 KST 날짜인지 항목별 의미 확인 전 일괄 변환 금지. 날짜만 아는 행사는 ‘시간 미정’으로 표시합니다.
**P1 · 결과 카드:** 날짜·아티스트·일정명·국가/도시·상태·공식 출처·저장·상세. 날짜순 그룹과 관심 사진으로 스캔. 행사 포스터 권한 미확인일 때 아티스트 사진을 ‘포스터’로 가장하지 않습니다.
**P1 · 돌아오기:** 상세·로그인·관심 관리에서 대상·국가·아티스트·날짜·정렬·페이지·스크롤 복구. 필터를 바꾸면 페이지는 첫 페이지로.
**P2:** 월간 달력 보조 보기·예매 알림·캘린더 내보내기는 별도. 이번 시안은 리스트부터 검토합니다.

## 입력 계약 제안 · 아직 API에 없음
| 입력 | 허용값·기본값 | 소유·이벤트 |
|---|---|---|

| sourceUrl/verifiedAt/status | 출처·검수 시각·예정/변경/취소/미확인 | 자료 소유. 취소가 확인되면 일반 예정과 구별 |

추천 API 설계는 새 공개 event-feed와 인증된 me/event-feed를 구분하고, 기존 배열 형태의 /events 계약은 유지하는 것입니다. 신규 피드는 items·totalCount·facets·page 정보를 동일 필터로 계산하고 안정적인 날짜+ID 순서를 사용합니다. 개인 피드는 현재 계정으로 서버 조회, credentials:include 및 private/no-store, 계정 간 캐시 혼입 방지가 필요합니다. 이름·클라이언트 user ID만으로 개인 범위를 신뢰하지 않습니다. 상위 N건을 받은 뒤 브라우저에서 필터링하고 전체 건수라고 표시하지 않습니다.

## Before / After 읽는 법
Before는 이번 운영 실캡처입니다. After는 독립 HTML로 렌더한 **미구현 예상 GUI 캡처**입니다. BTS·BLACKPINK·TWICE 사진은 이전에 출처를 기록한 공개 자료이며, 표시된 공연·날짜·장소·저장 상태는 전부 가상 예시입니다. 시안 클릭은 운영·계정·DB를 호출하지 않습니다. 국내·해외 캡처와 모바일 비교, 별도 클릭 시안을 제공합니다.

도우미에게 전달할 요청문: “이 팬 일정 시안을 기준으로 구현 명세를 확정해줘. 기존 관심 저장 관계를 재사용하고 국내·해외·온라인·미확인 분류 및 현지 날짜 계약을 먼저 검수해줘. 데이터 검수 결과와 화면 구현을 구분하고 두 계정·시간대·필터 복귀 테스트를 준비해줘.”
완료 증거: 국가·도시·시간대·출처 품질 표, 개인 피드 범위 검증, Before/After와 실제 동작 기록. 실패 시 미확인 자료를 추정 분류하지 않고 보완 대상에 남깁니다.
이번은 사용자 요청대로 분석·보고 단계입니다. 서비스 코드 수정·DB 변경·배포·알림 발송은 실행하지 않았습니다.
