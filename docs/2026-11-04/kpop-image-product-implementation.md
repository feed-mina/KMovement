# 사진 속 상품 후보 찾기 구현

2026-11-04. 화면 설계 보고서에 따른 코드 변경입니다. 운영 활성화·실제 상품 검색 품질을 확인한 기록과 구분합니다.

## 바뀐 사용 흐름

1. 공개 상품 페이지에서 사진 올리기 / 이미지·게시물 주소 / 상품명·브랜드를 고릅니다.
2. 사진 주소는 로그인 후 불러옵니다. 공개 게시물의 사진이 여러 장이면 한 장을 선택합니다. 로그인 제한 페이지는 직접 업로드로 안내합니다.
3. 아티스트는 검색해서 직접 선택하거나 모르면 건너뜁니다. 얼굴로 신원을 추정하지 않습니다.
4. 물건 부분을 드래그하거나 위치·너비·높이 조절 막대로 고릅니다. 선택한 부분만 JPEG로 변환하여 업로드합니다.
5. 작업 상태를 조회하고, 후보·모델 미연결·후보 없음·작업 오류를 구분합니다. 제출 응답을 받지 못한 경우 같은 업로드와 중복 방지 키로 다시 시도합니다.
6. 작업 완료 후 업로드 사진을 삭제할 수 있습니다. 사진·품목·아티스트 선택이 바뀌면 이전 응답을 버립니다.

## 운영에 연결하려면

기존 업로드 저장소와 media 큐 작업자의 연결이 필요합니다. 기존 작업자는 모델 미연결 상태에서 빈 후보를 반환했습니다. 이제 `availability=MODEL_NOT_CONFIGURED`를 전달하여 화면에서 별도 안내합니다.

선택 사항인 OpenCLIP 이미지 비교 엔진은 다음 운영 설정과 자료가 있어야 실행됩니다. 설정이 없으면 모델을 내려받거나 GPU·유료 API를 자동으로 실행하지 않습니다.

| 설정 | 내용 |
| --- | --- |
| `KPOP_PRODUCT_IMAGE_MANIFEST` | 검수한 상품 사진 목록 JSON의 절대 경로 |
| `KPOP_IMAGE_MODEL_CHECKPOINT` | 운영자가 준비한 신뢰할 수 있는 로컬 모델 가중치 파일 |
| `KPOP_IMAGE_MODEL_NAME` | 가중치와 일치하는 OpenCLIP 구조. 기본값 `ViT-B-32` |
| `KPOP_IMAGE_SOURCE_BUCKET` | 기존 업로드의 비공개 원본 버킷 |
| `KPOP_IMAGE_MIN_SIMILARITY` | 이미지 특징의 코사인 유사도 최소값. 기본 0.25는 기술 기본값이며 품질 검증·보정 필요 |

작업자에 `deploy/kpop_image/requirements.txt`의 선택 의존성을 설치하고 기존 S3 읽기 권한을 연결합니다. 모델 파일은 신뢰할 수 있는 배포본만 사용하고 이용 조건을 확인합니다. Hostinger에서 CPU로 실행하며 속도·메모리는 운영 자료로 측정해야 합니다.

상품 이미지 목록 예시입니다. 이 번호가 운영 상품이라는 뜻은 아닙니다.

```json
[
  {
    "productRef": "manual:123",
    "image": "images/product-123.jpg",
    "itemCategory": "bag",
    "artistIds": [1],
    "rightsChecked": true
  }
]
```

사진은 JSON 파일이 있는 폴더 아래에 둡니다. 최대 500장, JPG·PNG·WebP, 이미지별 10MB·2,500만 화소 이하입니다. `productRef`는 PostgreSQL의 `provider_product_ref` 또는 상품 번호와 일치해야 합니다. 아티스트를 선택했다면 목록의 `artistIds`로 좁힙니다. 공식 착용 근거를 자동 생성하지 않습니다. 권리를 검토하지 않은 사진은 제외합니다.

모델은 상품 이름·판매처·아티스트 신원을 만들지 않고 후보 번호와 외형 유사 근거만 반환합니다. Spring에서 승인된 원본 카탈로그를 다시 조회하고, 근거 등급·설명·출처·확인 시각을 검증합니다. 공개 링크는 기존 권리 조건을 따릅니다. 시각 유사 후보의 등급은 SIMILAR이며 유사도는 착용 확률로 노출하지 않습니다.

## 주소 수집의 범위

인증된 사용자의 주소 수집만 허용하고 Origin을 검사합니다. 사용자별 프로세스 내 분당 12회 제한이며 여러 웹 인스턴스를 사용할 때는 공통 저장소 기반 제한을 별도로 적용해야 합니다. 외부 HTTPS와 표준 포트만 허용합니다. DNS 결과의 공용 IPv4를 검사한 뒤 같은 주소에 연결을 고정합니다. 리디렉션마다 다시 검사합니다. IPv6 전용 사이트는 직접 업로드 대안을 사용합니다.

원격 요청에 사용자의 쿠키·인증 헤더를 전달하지 않습니다. 사진은 최대 10MB, HTML은 최대 1MB, 리디렉션은 최대 3회입니다. 페이지 스크립트를 실행하거나 로그인·접근 제한을 우회하지 않습니다. HTML 문자 인코딩이 UTF-8이 아니거나 자바스크립트로만 사진을 표시하는 사이트는 수집에 실패할 수 있습니다.

## 검증 기록

- 프론트엔드 집중 검사: 37개 통과. 사진 선택·잘못된 파일·로그인 제한·품목 선택·작업 재시도·주소 실패·오래된 응답 차단·공개 검색 회귀·DNS 연결 고정·내부 주소 리디렉션 차단을 확인했습니다.
- 이미지 비교 단위 검사: 5개 통과. 색상 벡터를 쓰는 시험용 인코더로 후보 정렬과 중복 제거를 검증했으며 실제 OpenCLIP 모델의 품질 검사는 아닙니다.
- Java 변경 클래스 3개 컴파일 성공. 상품·분석 서비스 테스트 메서드 15개를 별도 실행하여 통과했습니다.
- 변경 TypeScript 파일 5개에서 타입 진단 0개. 전체 프로젝트 타입 검사는 기존 Next·Firebase 선언 파일 누락으로 완료하지 못했습니다.
- 표준 Gradle 실행은 샌드박스의 캐시 잠금·데몬 연결 제한으로 완료하지 못했습니다. 기존 캐시 의존성으로 직접 컴파일하고 서비스 단위 검사를 대신 실행했습니다.
- FastAPI HTTP 통합 검사는 이 실행 환경에서 응답 대기가 끝나지 않아 중단했습니다. 통과로 계산하지 않습니다.

## 완료와 미확인

- 코드 구현: 입력 화면·사진 영역 선택·주소 수집·작업 연결·이미지 비교 선택 엔진·공개 근거 재검증.
- 실제 운영 설정: 모델 가중치·권리 확인한 상품 참조 사진·버킷 읽기 권한·작업자 연결을 별도 확인해야 합니다.
- 최종 검증 결과와 PR 링크는 작업 완료 안내에 기록합니다. 검증이 막힌 부분은 통과로 표기하지 않습니다.

원본 사진이나 운영 비밀값은 이 문서에 포함하지 않습니다.
