# K-POP 웹 접근성·상태 관찰 QA 계약

## 적용 범위

- Next.js 웹의 `ARTIST_CARD`, `EVENT_CARD`, 상품 후보 카드
- 사진 선택·업로드 동의와 분석 작업 진행 화면
- 근거 수준 배지, 공식 출처 링크, 저장·팔로우·일정 저장 상태

이 계약은 `subproject/SDUI/kride` 웹 배포에 적용한다. Expo 모바일은 렌더러와 접근성 API가 달라 별도 기기 QA가 필요하며, 웹 배포 성공이나 Lighthouse 결과로 모바일 완료를 대신하지 않는다.

## 구현 기준

- 모든 동작은 네이티브 `button`, `a`, `input`, `form`을 사용해 Tab 이동과 Enter/Space 실행을 지원한다.
- 포커스는 3px 고대비 외곽선으로 표시하고 주요 터치 대상은 최소 44px 높이를 유지한다.
- 카드 제목과 설명을 `aria-labelledby`/`aria-describedby`로 연결하고 이미지에는 대상과 용도를 설명하는 대체 텍스트를 제공한다.
- 팔로우·저장은 `aria-pressed`, 비동기 처리는 `aria-busy`, 분석 진행은 `role="progressbar"`와 현재 퍼센트를 제공한다.
- 근거 수준은 색만 사용하지 않고 `근거 수준:` 문구, 기호, 상세 근거를 함께 표시한다.
- 업로드·검색·저장 상태는 `role="status"` 라이브 영역, 복구가 필요한 실패는 `role="alert"`로 전달한다.
- 서버·스토리지의 원문 오류는 화면에 출력하지 않는다. 로그인, 파일 형식·용량, 요청 제한처럼 사용자가 조치할 수 있는 범주만 안전한 문구로 변환한다.

## 자동 확인

- 카드의 키보드 Enter/Space 실행, 이미지 대체 텍스트, 출처 안내
- 업로드 설명 연결, 미리보기 대체 텍스트, 진행률 숫자와 ARIA 값
- 근거 배지의 텍스트 레이블, 저장 상태의 `aria-pressed`
- 검색창 Enter 제출과 오류 원문 비노출

## 배포 전 수동 확인 게이트

- 실제 배포 URL에서 키보드만으로 카드 → 업로드 → 결과 → 저장 흐름 완료
- Chrome Lighthouse 접근성 검사와 브라우저 확대 200%에서 가림·초점 손실 확인
- Windows Narrator 또는 NVDA로 카드 이름, 근거 수준, 진행률, 상태 변경 순서 확인
- 모바일 브라우저에서 44px 터치 대상과 가로 320px 레이아웃 확인
- 실시간 SSE 실패 시 자동 새로고침 문구와 진행률이 계속 전달되는지 확인

자동 테스트와 빌드는 위 수동·배포 환경 검증을 대신하지 않는다. 현재 웹에는 승인된 클라이언트 진단 수집기가 없으므로 별도 원격 텔레메트리는 추가하지 않았으며, 민감한 오류 원문도 로그나 UI에 남기지 않는다.
