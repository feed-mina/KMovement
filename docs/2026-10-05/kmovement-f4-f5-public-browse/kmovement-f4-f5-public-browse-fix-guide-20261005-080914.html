전체 목표 › 공통 게이트 › 공개 경로

1. 읽기 전용 입구부터 고정

현재 문제: Spring Security는 공개 GET을 허용하지만 Hostinger proxy에는 tour 전용 라우터가 없습니다.

정확한 행동: areas, poi, restaurants, holy, holy/contents의 GET만 allowlist하고 POST submission과 admin은 열지 않습니다. TourAPI secret 이름만 configtree로 연결합니다.

완료 증거: compose config, GET 200/의도한 오류, POST·admin 차단, 80/443 외 공개 포트 없음.

실패하면: 새 tour router만 제거하고 기존 health·주소검색·웹을 유지합니다.

전체 목표 › F4 › 공급자와 페이지

2. F4는 실제 서버 다음 페이지까지

현재 문제: 화면은 24건만 받고 “더 보기”는 새 pageNo를 요청하지 않습니다. poi와 restaurants 두 계약도 섞여 있습니다.

정확한 행동: restaurants를 대표 계약으로 고정하고 areaCode, sigunguCode, arrange, numOfRows, pageNo를 통일합니다. 필터 변경 시 1페이지로 초기화하고 다음 결과를 ID 중복 없이 이어 붙입니다.

완료 증거: 서울/종로/정렬, 서로 다른 1·2페이지, 빈 결과, 공급자 오류, 마지막 성공 cache 표시.

실패하면: F4 탭만 비활성화하고 F5 DB 경로는 유지합니다.

전체 목표 › F5 › 승인 데이터

3. F5는 예시가 아닌 APPROVED DB만

현재 문제: 운영 API는 500이고 일반 성지는 정적 예시로 조용히 대체될 수 있습니다. K-POP 랜딩도 기본 맛집 탭으로 연결됩니다.

정확한 행동: 성지 링크에 category를 전달하고 공개 결과는 비공공 APPROVED만 표시합니다. MVP 종류는 전체/성지 맛집으로 고정하며 작품·아티스트 선택을 함께 씁니다.

완료 증거: PENDING/REJECTED 미노출, 지역·작품·FOOD 조합, 좌표·출처, 오류 시 재시도.

실패하면: F5만 숨기고 F4와 공통 지역 기능을 유지합니다.

전체 목표 › 검증 › 독립 장애

4. 같이 만들고 따로 깨뜨려 보기

현재 문제: 화면 200은 데이터 기능 성공이 아닙니다.

정확한 행동: F4 공급자 실패, F5 DB 실패, 지역 실패를 각각 만들어 loading/empty/error/ready를 확인합니다. 데스크톱·모바일과 키보드 상세 모달도 확인합니다.

완료 증거: 단위·화면 테스트, 네트워크 응답, 1·2페이지 ID, 승인 상태 대조, 두 기능 독립 결과.

실패하면: 통합 배포를 멈추고 통과한 기능만 유지 가능한지 판정합니다.

전체 목표 › 배포 › 두 줄 판정

5. 한 배포 기록 안에서 F4·F5 분리

현재 문제: 컨테이너가 healthy여도 공개 조회는 실패할 수 있습니다.

정확한 행동: main SHA, image digest, config revision, target, rollback digest를 기록하고 F4·F5의 정상·빈값·오류 검증을 별도 행으로 남깁니다.

완료 증거: 원격 PR, digest 고정, live 화면·API, rollback rehearsal.

실패하면: feature gate나 router 단위로 한쪽만 되돌립니다.
