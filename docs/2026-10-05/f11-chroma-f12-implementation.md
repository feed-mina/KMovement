# F11 → Chroma → F12 로컬 구현·검증

현재 단계: 로컬 구현과 제한된 통합 검증. main 병합·원격 CI·운영 배포는 미실행.

## 변경

- F11: 좌표·지원 도로 거리·동일 지점 검사, 실제 도로 경로와 명시적인 왕복 코스, 주변 시설·장소, 날씨 대체 안내, 지도 선을 연결했다. 공통 API 전달 규칙이 새 동적 핸들러를 Spring으로 넘기던 문제도 수정했다.
- Chroma: 전용 공개 장소 컬렉션, CPU E5 임베딩 접두사·모델 계약, 영속 색인, 삭제 동기화와 조회 시 현재 공개 목록 재확인을 추가했다.
- F12: 서버가 확인한 로그인 사용자, 내부 서비스 인증, 공개 후보 ID로 제한한 생성, 생성 후 승인 재확인, 임의 장소·중복 제거, 요청 기간 제한, 마커와 출처를 연결했다.
- F12 비용: 영속 SQLite 예약 장부, 한국 날짜 기준 사용자당 하루 10회, 전체 동시 2회, 일일 비용 한도, 자동 재시도 제거. 실패한 예약도 당일 한도에 남고 실제 사용량 비용은 설정 단가에 따른 추정치이다.
- 별도 CPU 서비스 구성과 적용 안내를 준비했다. 이 서비스는 사용자 이력과 jobs 경로를 노출하지 않는다.

## 확인한 증거

- Python 회귀 시험 55개 통과. 마지막 F12 변경 후 관련 6개 재시험 통과(55개와 중복되는 시험이며 합산하지 않음).
- 화면·인증 프록시·오류 문구 시험 15개 통과. 소스 전용 TypeScript 검사 통과.
- 실제 로컬 웹 → API → 저장소 도로 그래프 → 지도 선을 360·390·768·960·1440px에서 확인했다. 경로 200, 동일 지점 422, 이전 지도 제거, 가로 넘침 없음. 관계없는 인증·공개 목록 화면 데이터는 시험용 응답이었다.
- 실제 그래프에서 2km 왕복 경로와 시작점 복귀 확인. 왕복은 거리 중심이며 안전·관광 가중치로 선정하지 않는다.
- 실제 persistent Chroma 재개방·색인 중복·삭제·공개 취소 제외 확인. 실제 E5 CPU 검색은 합성 질문 3개에서 기대 top-1 3/3. 운영 검색 품질이나 부하 보증은 아니다.
- 운영 공개 응답 300건 모두 sourceUrl 없음. 추가 읽기 전용 DB 집계: APPROVED/CRAWL 9,017건, APPROVED/SEED 8건의 source_url 기록이 모두 0건. DB 집계는 관광 자료 전체 범위이다.
- 실제 로컬 추천 요청은 empty_candidates, 빈 장소·마커, usage=null. 정상 생성·임의 장소 제외·비용 기록은 모의 공급자 응답으로 시험했고 실제 유료 생성은 실행하지 않았다.

## 남은 조건

1. 실제 장소 출처를 확인해 보완 목록을 준비한다. 링크를 추측하거나 이미지 출처를 장소 근거로 대체하지 않는다. 운영 자료는 이번에 수정하지 않았다.
2. 현재 후보 범위는 공개 성지 API가 반환하는 최대 300건이다. 음식·자연 전용 자료 확장과 전체 관광 자료 검색 품질은 미완료이다.
3. 운영 고정 버전 이미지로 빌드·재시험해야 한다. 로컬 시험 환경의 일부 라이브러리 버전은 requirements-docker.txt와 다르다. 전체 기존 TypeScript 설정은 오래된 .next 참조가 있어 전체 빌드 성공을 주장하지 않는다.
4. 실제 로그인 서비스 연결, 공급자 정상 생성·사용량, 동시 부하·메모리, 운영 화면을 확인한다. 여행 지출·영업시간·현장 이동 가능성은 보장하지 않는다.
5. pgvector 설치, 사진 업로드, 분석 jobs, 저장 기능, 결제는 이 작업에 포함하지 않았다.
