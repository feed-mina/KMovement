RAG 검색 실패와 생성 실패를 분리하는 조사·검증 계획

핵심: 디밀리언 47:23~51:32의 질문에 답하려면 기술 이름이 아니라 실패 사례의 query → retrieved evidence → context → answer 전 과정을 보여줘야 합니다.

다음 행동 하나: 면접에서 언급한 실제 오답 질문을 평가셋 첫 행으로 복원합니다.

3줄 줄거리와 현재 위치

  1. 정답 문서가 무엇인지 먼저 고정하지 않으면 검색 품질을 측정할 수 없습니다.
  2. 필터·벡터·혼합·재정렬은 같은 평가셋으로 비교해야 합니다.
  3. 검색이 맞은 뒤에도 생성 근거성과 인용 일치성을 별도로 판정해야 합니다.

현재 위치: [근거 없는 답변 차단] 중 [평가 계약]의 [실패 질문·기대 근거 정의] 단계입니다.

확인: 공식 문서는 필터·점수 기준·혼합 검색을 제공일부 확인: KMovement 코드에는 임계값과 보류 프롬프트가 존재미확인: 운영 경로·임계값 보정·고정 평가 통과

조사 전 가설과 판정

가설검증현재 판정
오답은 비동기 순서 문제였다.동일 요청의 시간순 로그와 검색 결과를 재현해 순서 경합과 관련성 오류를 분리미확인. 면접 답변만으로는 검색 오류와 비동기 오류를 구분할 수 없음
거리 임계값만 넣으면 환각이 사라진다.정답·오답·근거 없음 질문의 점수 분포와 오탐/누락 비교반증 가능성이 큼. 임계값은 검색 결과를 거를 뿐 생성 준수를 보증하지 않음
재정렬을 넣으면 항상 좋아진다.동일 평가셋에서 검색 방식별 Recall@k, 잡음률, 보류 정확도 비교미확인. 운영 경로와 평가 결과가 필요
출처 이름을 붙이면 근거 답변이다.답변 주장과 인용 청크의 내용 일치 검사반증. 안정적 출처 ID와 인용 검증이 필요

클릭형 조사 지도

A1. 평가셋

현재 문제: 예제 4개나 임의 질문은 실제 실패를 대표하지 못합니다.

사용자 직접 할 일: 틀렸던 질문과 기대 장소를 확인합니다.

에이전트 역할: 최소 초기 20개 이상을 정상·정확필터·유사이름·잘못된전제·근거없음·오래된정보로 나눕니다.

완료 증거: 각 행에 expected_source_ids와 should_abstain이 있습니다.

A2. 검색 비교

현재 문제: “가장 가까운 결과”가 정답인지는 별도입니다.

사용자 직접 할 일: 없음.

에이전트 역할: 필터+벡터, 벡터만, 키워드+벡터, 재정렬을 같은 입력으로 비교합니다.

완료 증거: 질문별 문서 ID·원시 거리·정규화 점수·순위·필터가 남습니다.

A3. 임계값 보정

현재 문제: 숫자 하나를 주석으로 정한 것은 운영 기준의 근거가 아닙니다.

에이전트 역할: 정답과 오답 점수 분포를 비교하고, 임계값별 false accept/false reject를 계산합니다.

완료 증거: 선택 임계값과 포기한 정답/차단한 오답 수가 함께 제시됩니다.

A4. 생성·인용

현재 문제: 프롬프트 지시는 실행 보장이 아닙니다.

에이전트 역할: 올바른 컨텍스트·틀린 컨텍스트·빈 컨텍스트를 각각 넣어 답변 준수와 보류를 검사합니다.

완료 증거: 모든 사실 주장에 안정적 source/chunk ID가 연결되고, 불일치 인용은 실패 처리됩니다.

A5. 실패 원인 로그

현재 문제: 한 줄 오류만으로는 고칠 축을 고를 수 없습니다.

에이전트 역할: retrieval_miss, retrieval_noise, generation_unsupported, citation_mismatch를 기록합니다.

완료 증거: 각 실패에 돌아갈 담당 단계가 하나로 정해집니다.

에이전트에게 그대로 전달할 요청문

목표: 검색 결과와 생성 답변을 분리 평가하고, 근거가 약하면 생성하지 않는지 증명한다.
대상: 실제 운영 RAG 진입점과 고정 평가셋.
확인된 사실: 정확 ID·날짜·상태는 의미 검색보다 필터가 우선이며, 검색과 생성은 서로 다른 실패 축이다.
미확정 가설: 현재 점수 기준과 재정렬이 실제 실패 질문에서도 유효하며 운영 경로에 연결돼 있다.
맡길 범위: 읽기 전용 경로 추적, 평가셋 초안, 검색 방식·점수 기준 비교 계획, 로그 스키마와 출처 계약 제안. 코드 변경·배포·운영 데이터 쓰기 금지.
완료 기준: 질문별 기대 근거, 검색 결과 ID/점수/순위, 생성에 전달한 컨텍스트, 답변과 인용, 보류 여부, 실패 단계가 한 행으로 연결된 보고서.

사용자가 지금 직접 할 일: 면접에서 틀렸던 실제 질문과 기대했던 장소·문서를 확인하는 일뿐입니다. 나머지는 아직 실행 요청이 아닙니다.

Before / After

Before

검색 결과와 답변만 보고 “틀렸다”고 기록합니다. 원인이 검색인지 생성인지 알 수 없습니다.

After · 제안 계약

필터 → 후보 → 점수·순위 → 임계 판정 → 전달 컨텍스트 → 답변 → 인용 → 실패 단계가 연결됩니다.

설계안이며 구현·테스트 완료 상태가 아닙니다.

공식 근거와 적용 한계

  • Vector embeddings: 벡터 거리는 텍스트 관련성을 나타내며 사실성 판정은 별도입니다.
  • Retrieval: 속성 필터, 점수 임계값, 하이브리드 가중치를 비교할 수 있습니다.
  • Optimizing LLM Accuracy: 검색 실패와 모델 실패를 별도 축으로 평가하며, 초기 20개 이상의 정답 포함 질문을 기준선으로 제시합니다.
  • Citation Formatting: 안정적 출처 단위·표현·형식·파싱 검증이 필요합니다.

완료 상태: 조사 계획과 판정 계약만 작성했습니다. 평가 실행, 임계값 변경, 코드 수정, 배포는 하지 않았습니다.
