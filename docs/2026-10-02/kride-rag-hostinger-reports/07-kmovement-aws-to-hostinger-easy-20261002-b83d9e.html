KMovement 서버 이사 안내

집을 바로 비우지 않고 새집을 먼저 준비해 모든 짐과 전기를 확인한 뒤 주소를 바꾸는 계획입니다. 지금은 조사와 보고서만 끝났고 실제 이사나 주소 변경은 하지 않았습니다.

다음 행동 하나: Hostinger 서버 사양과 현재 AWS 서버의 사용량·데이터 크기를 한 표로 확인하세요.

3줄 줄거리

1. 새 Hostinger 서버를 먼저 만들고 현재 서비스와 나란히 켭니다.
2. 회원·화면·여행 검색 자료를 복사한 뒤 로그인과 추천을 시험합니다.
3. 모두 통과했을 때만 인터넷 주소를 새 서버로 바꾸고 AWS는 잠시 남겨 둡니다.

클릭해서 확인하는 이삿짐 지도

웹사이트와 문

현재 상황: 한 인터넷 주소가 화면, 회원 기능, 여행 추천으로 길을 나눕니다.

내가 할 일: 새 서버에서도 같은 주소 규칙과 자물쇠 표시가 되는지 확인합니다.

도우미에게 부탁할 말: “임시 주소에서 메인·여행·맛집 화면과 실시간 응답을 확인해 주세요.”

끝난 표시: 네 화면이 열리고 보안 경고가 없습니다.

회원과 저장 자료

현재 상황: 회원 정보, 화면 설정, 검색 자료는 서버의 여러 보관함에 나뉘어 있습니다.

내가 할 일: 복사 전후 개수와 날짜를 받아 보관합니다.

도우미에게 부탁할 말: “회원·화면·검색 자료의 복사 전후 개수와 복원 시험 결과를 보여 주세요.”

끝난 표시: 기존 계정으로 로그인하고 새 저장도 됩니다.

여행 추천과 영상 작업

현재 상황: 새 서버가 여행 질문을 받고, 무거운 영상 작업은 바깥 전문 서비스에 맡깁니다.

내가 할 일: 추천 한 번과 영상 작업 한 번의 결과 주소를 확인합니다.

도우미에게 부탁할 말: “추천·실시간 진행·완성 파일 주소까지 한 건씩 시험해 주세요.”

끝난 표시: 진행 상태가 멈추지 않고 결과를 열 수 있습니다.

업로드 파일

현재 상황: 일부 파일은 AWS의 별도 파일 창고를 사용합니다.

내가 할 일: 이번에 그 창고를 유지할지, 나중에 따로 옮길지 결정합니다.

도우미에게 부탁할 말: “서버 이사와 파일 창고 이사를 한 번에 하지 말고 각각 성공 기준을 작성해 주세요.”

끝난 표시: 올리기·보기·삭제가 모두 시험되었습니다.

주소 바꾸기와 되돌리기

현재 상황: 주소를 바꾸기 전까지 사용자는 AWS를 계속 봅니다.

내가 할 일: 변경 시간과 되돌릴 사람을 정합니다.

도우미에게 부탁할 말: “변경 직전 마지막 복사, 30분 확인, 실패 시 되돌리기 순서를 기록해 주세요.”

끝난 표시: 외부 휴대폰에서도 새 서버가 열리고 AWS 되돌리기도 시험했습니다.

현재 · 확인된 구조

AWS가 서비스 집 역할

화면과 여행 추천, 저장 자료가 AWS 서버 주변에 모여 있습니다. 서버에만 있는 검색 자료와 인증 파일이 있습니다.

예상 모형 · 아직 미실행

Hostinger가 새 서비스 집

같은 기능을 새 서버에서 먼저 확인한 뒤 주소를 바꿉니다. 무거운 영상 도우미와 외부 데이터 서비스는 그대로 연결합니다.

아직 모르는 것과 확인법

  • 서버 크기: 현재 가장 바쁜 시간의 사용량과 저장 크기를 보고 정합니다.
  • 회원 자료: 백업 파일을 새 서버에 실제로 복원해 로그인으로 확인합니다.
  • 검색 자료: 복사 전후 자료 개수와 같은 질문의 결과를 비교합니다.
  • AWS 파일 창고: 이번에는 유지할지, 별도 두 번째 이사로 옮길지 정합니다.
  • 완료: 단순히 새 서버가 켜진 것이 아니라 화면·로그인·추천·저장·복구가 모두 통과해야 합니다.

공식 안내상 Hostinger는 Docker 방식의 서버 운영, 자동 배포, 방화벽, 백업·스냅샷을 제공합니다. 하지만 KMovement 자료 복사와 정상 동작 확인은 별도로 해야 합니다.
