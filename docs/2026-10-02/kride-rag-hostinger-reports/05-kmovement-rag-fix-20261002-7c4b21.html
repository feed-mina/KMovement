KMovement RAG: 검색과 생성을 분리해 고칠 위치

핵심: 현재 코드는 QA·추천·일정·Kaggle 변형이 서로 다른 검색 안전장치를 가집니다. 먼저 실제 운영 경로를 확정하고, 공통 결과 계약을 만든 뒤, 경로별 보류 조건을 시험해야 합니다.

다음 행동 하나: 운영 화면의 네트워크 요청과 서버 버전을 확인해 main FastAPI와 Kaggle 중 실제 경로를 고정합니다.

3줄 줄거리와 현재 위치

  1. QA에는 distance <= 0.25가 있지만 출처·점수는 응답에서 사라집니다.
  2. 추천에는 같은 임계값이 없고, 일정은 POI 0건이어도 생성 호출을 계속할 수 있습니다.
  3. 고정 평가셋과 공통 provenance 계약 없이 한 경로만 고치면 면접 질문에 증거로 답할 수 없습니다.

현재 위치: [KMovement 근거 기반 답변] 중 [실행 경로 확정]의 [배포 경로와 평가 기준 확인] 단계입니다.

클릭형 수정 지도

P0. 실제 경로부터 고정

현재 문제: main FastAPI와 Kaggle 서버의 검색 방식·응답 필드가 다릅니다.

사용자가 직접 할 일: 운영 화면 주소와 테스트 계정 범위를 지정합니다.

에이전트 요청: 브라우저 네트워크, Spring 설정, FastAPI health/version, 배포 로그를 읽기 전용으로 대조한다.

완료 증거: 화면 요청 URL → Spring → FastAPI 프로세스 → Git SHA가 한 표로 연결됩니다.

실패하면: 코드 수정을 보류하고 배포 식별자 확보 단계로 돌아갑니다.

P1. 실패 질문·기대 근거

현재 문제: 예시 4개 top-1 평가는 면접의 잘못된 장소 사례를 재현하지 않습니다.

에이전트 요청: 실제 오답, 유사 장소, 다른 지역, 근거 없음, 폐업/오래된 상태를 포함한 고정 평가셋을 만든다.

완료 증거: 각 질문에 기대 POI/문서 ID와 보류 정답이 있습니다.

P2. 공통 검색 결과 계약

현재 문제: 내부 검색 결과는 text·metadata·distance를 갖지만 최종 응답은 문장만 남깁니다.

제안 필드: retrievedEvidence[], sourceId, collection, rawDistance, normalizedScore, rank, filters.

영향 파일: Python 응답 → Java DTO/Service → TypeScript 타입/화면을 함께 맞춥니다.

완료 증거: 한 질문의 검색 결과가 API 응답과 화면에서 같은 ID로 보입니다.

P3. 코드 수준 답변 보류

현재 문제: 프롬프트에만 “지어내지 말라”고 쓰면 모델 호출 자체는 계속됩니다.

제안: 검증된 근거가 0건이면 LLM을 호출하지 않고 구조화된 abstained=true, reason, failureStage를 반환합니다.

일정 우선: poiGrounded=false일 때 생성 전에 종료하거나 명시적 사용자 재질문 상태로 전환합니다.

완료 증거: mock LLM 호출 횟수가 0이고 화면에 보류 이유가 표시됩니다.

P4. 필터·혼합·점수 비교

현재 문제: 지역 후처리는 관련 없는 후보를 먼저 뽑은 뒤 버릴 수 있습니다.

제안 실험: 정확 metadata filter → dense search, dense only, keyword+dense, rerank를 동일 평가셋에서 비교합니다.

측정: Recall@k, noise@k, false accept, false reject, abstention accuracy.

주의: distance와 similarity 방향을 같은 표에서 혼용하지 말고 변환 규칙을 고정합니다.

P5. 출처와 실패 로그

현재 문제: 화면의 일반 오류만으로 검색·생성·인용 실패를 구분할 수 없습니다.

제안: 답변 문장에 stable source/chunk ID를 연결하고, 서버에는 query·filters·results·threshold decision·context·answer·citations를 남깁니다.

실패 코드: retrieval_miss / retrieval_noise / generation_unsupported / citation_mismatch.

완료 증거: 한 실패가 하나의 단계와 담당 파일로 되돌아갑니다.

에이전트에게 그대로 전달할 요청문

목표: KMovement에서 검색 결과와 생성 답변을 분리하고, 근거가 약하면 LLM 호출 전에 답변을 보류하며, 사용자에게 실제 출처를 표시한다.
대상: feed-mina/KMovement의 실제 운영 RAG 경로. 기준 커밋은 먼저 배포 SHA와 대조한다.
확인된 사실: main QA는 distance 0.25 필터를 사용하지만 출처·점수를 반환하지 않는다. 추천에는 같은 임계값이 없고, 일정은 poiGrounded=false여도 생성 호출을 계속할 수 있다. Kaggle 경로는 재정렬과 sources가 있으나 운영 연결은 미확인이다.
미확정 가설: 현재 운영이 main 경로이며 0.25 임계값이 실제 데이터에 맞고, 기존 MLflow 실험이 현행 경로의 회귀 품질을 증명한다.
맡길 범위: 1) 운영 경로 읽기 전용 확인 2) 실제 실패 질문 기반 고정 평가셋 초안 3) 검색 결과·보류·출처 응답 계약 제안 4) 변경 파일과 테스트 계획. 이 단계에서는 코드 변경·DB 쓰기·배포 금지.
완료 기준: 화면 요청부터 검색·생성·응답까지 실제 경로가 고정되고, 질문별 기대 근거·검색 순위/점수·보류 정답·실패 단계가 기록되며, 수정 전후 테스트 목록이 제시된다.

사용자가 지금 직접 할 일: 운영 화면과 면접 당시 실패 질문을 지정하는 것. 그 외 수정·배포 행동은 아직 없습니다.

Before / After

Before

경로별 안전장치가 다르고, 답변 문자열이 검색 근거를 잃은 채 화면으로 옵니다. 무근거 일정도 생성 호출 가능성이 있습니다.

After · 제안 계약

모든 경로가 같은 evidence/abstention/citation/failureStage 계약을 쓰며, 근거 0건은 생성 전에 멈춥니다.

아직 구현·테스트되지 않은 목표입니다.

근거와 현재 완료 상태

  • OpenAI Embeddings: 의미 유사도와 사실 정확성은 별개로 평가해야 합니다.
  • OpenAI Retrieval: 속성 필터·score threshold·hybrid search를 비교할 수 있습니다.
  • Optimizing LLM Accuracy: retrieval과 generation 실패를 분리합니다.
  • Citation Formatting: 안정적 인용 단위와 검증이 필요합니다.
완료: 공개 코드 정적 분석과 수정 범위·검증 계약 작성.
미완료: 운영 경로 확인, 평가 실행, 코드 수정, 테스트, 브라우저 확인, 배포.
