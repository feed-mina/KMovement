# KMovement 전체 로직 수정·장애 대응 안내서

기준: `feed-mina/KMovement` `main` · `0c6e278f1` · 2026-10-02

## 1. 화면이 비거나 잘못 보임

현재 문제: 화면 번호·역할·화면 트리·데이터 소스·컴포넌트 등록 중 하나가 맞지 않으면 일부 또는 전체가 표시되지 않는다.

사용자 행동: 문제 주소, 로그인 역할, 비어 있는 영역과 직전에 누른 항목을 함께 남긴다.

에이전트 요청문:

> KMovement의 해당 화면을 분석해 주세요. 화면 번호와 사용자 역할을 확인하고, 화면 트리 응답의 부모·자식 구조, 선언된 데이터 소스, 반환 데이터 이름, 컴포넌트 등록 여부를 순서대로 대조해 주세요. 수정 전 원인과 영향 범위를 먼저 보고하고, 관련 테스트만 추가한 뒤 변경해 주세요.

완료 증거: 같은 역할의 노드와 화면 요소 대응, 빈 상태 표시, 키보드·모바일 폭 확인.

핵심 위치: `UiService.java` → `usePageMetadata.tsx` → `renderNodes.tsx` → 도메인 등록 파일.

## 2. 목록·저장·상세만 실패

현재 문제: 등록되지 않은 쿼리, 선언되지 않은 파라미터, 잘못된 반환 타입, 클라이언트가 보낸 사용자 ID는 거절된다.

에이전트 요청문:

> 실패한 데이터 요청의 등록 키를 찾고, 필요한 역할, 필수 파라미터, 파라미터 형식, 서버 주입 사용자 식별자, 반환 타입을 확인해 주세요. 요청과 본문의 중복 키 및 선언되지 않은 키를 제거하고, 다른 등록 쿼리에는 영향이 없는지 정책 테스트로 검증해 주세요.

완료 증거: 정상 결과 형식, 금지 파라미터 오류, 사용자별 데이터 격리.

핵심 위치: `CommonQueryController.java`, `QueryParameterPolicy.java`, `DynamicExecutor.java`, 관련 DB 마이그레이션.

## 3. 일정·지도·채팅이 어긋남

현재 문제: 추천 후보는 맞지만 좌표가 없거나, 일정과 채팅이 다른 문맥을 쓰거나, 외부 모델·지오코딩 실패가 부분 결과로 내려올 수 있다.

에이전트 요청문:

> 같은 여행 입력으로 추천 후보, 그래프 확장 후보, 생성된 일정, 좌표 해석 결과, 화면 마커를 단계별로 비교해 주세요. 직접 좌표, 원본 장소 매칭, 주소 변환의 우선순위를 확인하고, 채팅이 현재 일정을 같은 문맥으로 받는지 검증해 주세요. 외부 호출 없이 재현 가능한 테스트를 먼저 추가해 주세요.

완료 증거: 일정 장소와 마커 차이 설명, 결정적 변환 테스트, 외부 장애 대체 결과.

핵심 위치: `fastapi_server.py`, `rag_client.py`, `graphrag_client.py`, 프런트 일정 훅과 지도 컴포넌트.

## 4. 분석·영상 작업이 멈춤

현재 문제: 작업 접수 후 워커가 없거나 원격 엔드포인트·토큰이 다르거나 진행률 갱신이 끊기면 계속 대기처럼 보인다.

에이전트 요청문:

> 작업 번호를 기준으로 소유권, 동의 범위, 중복 방지 키, Redis 전달, 워커 수신, 원격 작업 번호, 마지막 상태 갱신을 추적해 주세요. 재시도 전에 기존 작업의 terminal 상태와 원본 만료·삭제 상태를 확인하고, 중복 과금이나 중복 결과가 생기지 않도록 해 주세요.

완료 증거: 대기 → 실행 → 성공/실패/취소/만료 전이, 중복 방지, 사용자 간 작업 격리.

## 5. 배포 뒤 DB와 화면이 다름

에이전트 요청문:

> 현재 배포 커밋, 프런트가 바라보는 업무·추천 서버 주소, Spring 활성 설정, Flyway 최신 성공 버전, 화면 정의와 등록 쿼리의 존재를 읽기 전용으로 대조해 주세요. 데이터 변경이나 롤백 전에는 차이와 복구 지점을 먼저 보고해 주세요.

완료 증거: 배포 SHA·이미지 일치, Flyway 상태, 화면 요청의 노드·데이터 계약 일치.

## 우선 위험

1. 현재 CI는 Spring 전체 테스트를 실행하지 않고 Celery 관련 두 테스트 클래스만 실행한다.
2. 모바일 테스트는 루트 CI에 포함되지 않는다.
3. DB의 화면 정의와 코드의 컴포넌트 등록표 중 하나만 바뀌면 화면이 조용히 빠질 수 있다.
4. 추천 이력은 best-effort 저장이므로 사용자 응답 성공과 분석 데이터 저장 성공을 따로 관찰해야 한다.
5. 운영 배포 버전, 외부 서비스와 사용자 수용은 이번 문서 작성에서 확인하지 않았다.
