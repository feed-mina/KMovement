AI 계층

SDUI 조립 축

screenId로 화면 정의를 받고, 데이터 소스를 실행한 뒤 컴포넌트 등록표로 실제 React 요소를 고릅니다. 웹과 모바일은 같은 화면 계약을 서로 다른 표현 컴포넌트로 해석합니다.

업무 API 축

/api/ui는 역할별 화면 트리를, /api/execute는 등록된 쿼리를, 도메인 API는 관광·K-POP·커뮤니티·인증·관리 업무를 제공합니다.

AI 축

/kride-api는 FastAPI의 /api로 중계됩니다. 일정 생성은 장소 검색·그래프 확장·LLM 생성·좌표 해석·이력 저장을 조합합니다.

운영 축

Redis는 캐시와 큐, PostgreSQL은 서비스 데이터, ChromaDB는 벡터 검색, Supabase는 그래프·이력, S3/Cloudinary는 미디어를 맡습니다. 각 저장소는 선택적 설정과 실패 정책이 다릅니다.

대표 흐름: 여행 조건 입력 → 일정 생성 → 지도·채팅으로 보완

1. 조건 선택기간, 아티스트, 지역, 목적, 예산을 폼 상태에 모읍니다.
2. 화면 계약화면 번호로 메타데이터와 선택지 데이터를 읽고 등록된 컴포넌트를 그립니다.
3. 추천 요청Next.js 중계가 FastAPI 일정 생성 요청으로 전달합니다.
4. AI 조합벡터·그래프 후보, 일정 생성, 좌표·맛집 보완, 이력 저장을 수행합니다.
5. 결과 사용일정 패널과 지도 마커를 공유하고 채팅으로 질문·추천·재계획을 이어갑니다.

데이터와 비동기 작업은 “원본·검색·캐시·파일”로 나뉩니다

PostgreSQL + Flyway

ui_metadata, query_master, 사용자·관광·K-POP·커뮤니티·작업 상태의 시스템 원본입니다. 109개 마이그레이션이 화면/쿼리/업무 스키마를 누적합니다.

Redis

K-POP 공개 조회 캐시, Celery 브로커·결과, 사용량 카운터에 쓰입니다. 사용자 범위 데이터와 명령형 쿼리는 공개 캐시에서 제외됩니다.

ChromaDB + 로컬 그래프

목적별 장소 임베딩 컬렉션과 models/kride_graph.json의 아티스트-장소 관계를 추천·채팅 문맥으로 사용합니다.

Supabase + 파일 저장소

그래프 미러·추천 이력과 커뮤니티/분석 미디어를 담당합니다. 설정이 없을 때 일부 이력은 로컬 JSONL 또는 비저장으로 내려갑니다.

로컬 시작 순서

  1. 환경 변수 예시를 기준으로 DB·Redis·외부 키를 준비합니다.
  2. Spring의 PostgreSQL/Flyway를 먼저 올립니다.
  3. FastAPI와 필요 시 Chroma·Celery 워커를 올립니다.
  4. Next.js 또는 Expo를 마지막에 연결합니다.

현재 CI 경계

루트 CI는 Next.js 테스트·빌드와 FastAPI 지정 테스트를 실행합니다. Spring은 전체 빌드를 테스트 제외로 수행한 뒤 Celery 관련 2개 테스트 클래스만 별도 실행합니다. 모바일 테스트는 이 CI 정의에 포함되지 않습니다.

배포·복구

EC2 배포, 프런트 전용 배포, RunPod 이미지 빌드, Supabase 그래프 적재·갱신이 분리되어 있습니다. 장애 시 최근 이미지/커밋, Flyway 적용 버전, 환경 변수, 외부 서비스 상태를 같은 시점으로 맞춘 뒤 한 계층씩 되돌립니다.
