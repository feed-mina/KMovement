# KRIDE UI 연결·일관성 조사 보고서

2026-10-06 / 조사·제안 완료, 구현·배포 미실행.

메인 → K-pop 탐색 → 저장 → 마이 재방문을 연결한다. 공개 실제 화면, 사용자 제공 내 목록 캡처, UI 소스를 대조했다. 로그인 후 동작은 미검증.

## 01 · 끊긴 연결 먼저

P1 · register.ts:20–21에 이벤트·상품 화면 등록이 존재합니다. 공개 브라우저에서 직접 URL로 두 화면을 열었습니다. PersonalSaved.tsx:59는 빈 목록 문구만 표시하며 탐색 링크가 없습니다. 메뉴 노출을 보강하고 저장과 탐색을 양방향으로 연결합니다.

제안: K-pop 안에 아티스트·이벤트·상품 메뉴를 두고, 빈 목록에는 해당 종류의 찾아보기 버튼을 둡니다.

완료 증거: 이벤트 찾아보기 → 이벤트 목록 → 상세 → 저장 → 마이페이지의 이벤트 목록 → 동일 상세로 복귀. 상품도 같은 흐름으로 확인합니다.

## 02 · 메인 첫 화면

app/page.tsx:19–42 및 MarketingNav가 소개 화면을 만듭니다. /travel/kpop은 여행 가이드이고 /view/kpop은 아티스트 목록이며 /view/INTRO1은 코스 시작 화면입니다. 세 목적을 같은 이름으로 섞지 말고 탐색 허브에서 구분합니다.

제안: 상단에 홈·K-pop·코스 만들기·마이를 고정하고, 이벤트와 상품을 K-pop 안에서 찾도록 묶습니다. 전국 맛집과 커뮤니티는 더보기 또는 탐색 안에서 유지합니다.

완료 증거: 처음 온 사람도 메인에서 K-pop과 마이를 찾고, K-pop에서 이벤트·상품으로 이동할 수 있어야 합니다.

## 03 · K-pop과 코스

AppShell.tsx:12,20,31의 KRIDE_PATHS 분기가 INTRO 화면의 공통 메뉴를 숨깁니다. /view/kpop은 screenMap에서 KPOP_EXPLORE로 해석됩니다. K-pop 탐색 하위 메뉴와 코스 작성 단계 표시를 분리하되 브랜드·뒤로·나가기 위치는 통일합니다.

제안: 탐색 화면에는 아티스트·이벤트·상품을 두고, 코스 만들기는 별도 큰 버튼으로 둡니다. 작성 중에는 이전·다음·나가기를 같은 위치에서 보여줍니다.

완료 증거: 휴대폰과 PC에서 현재 위치가 보이고, 코스에서 나갔다 돌아올 때 입력 보존 정책대로 동작해야 합니다. 보존 구현 여부는 아직 미확인입니다.

## 04 · 마이와 내 목록

AuthFlowScreen.tsx:148은 프로필에서 KPOP_SAVED_ITEMS로 연결합니다. PersonalSaved.tsx:36은 종류·페이지를 로컬 상태로만 관리하고, :60은 상품을 제목 검색으로 다시 엽니다. kind/page URL 상태와 안정된 상품 ID 상세 계약을 제안합니다. 개인 저장 데이터와 권한 규칙은 유지합니다.

제안: 마이에 저장한 아티스트·이벤트·상품 진입을 모읍니다. 숫자는 실제 불러온 값만 표시하고, 없으면 찾아보기 버튼을 보여줍니다. 계정 정보와 로그아웃은 아래로 둡니다.

완료 증거: 종류 선택 → 항목 보기 → 뒤로 이동 후 종류·페이지가 유지되어야 합니다. 동명이인·동일 제목 상품도 같은 항목이 열려야 합니다.

## 05 · 한 서비스처럼

marketing.module.css:1은 밝은 배경과 별도 글꼴, pages.css:4579는 검은 K-pop 배경, personal-saved.css:1은 별도 테두리 버튼입니다. tokens.css에 기존 색·간격·48px 터치 규칙이 있으므로 semantic 토큰을 재사용합니다. 새 디자인 체계를 중복 생성하지 않습니다.

제안: 밝은 배경·흰 카드·빨간 주요 버튼을 기본안으로 제안합니다. 검은 화면은 별도 선택 테마로 일관되게 적용할 때만 사용합니다. 시간 설정은 코스 관련 화면으로 옮기거나 작게 접습니다.

완료 증거: 같은 행동의 버튼·제목·카드·빈 화면이 세 페이지에서 같은 모양이어야 합니다. 테마 선택과 48px 버튼 높이는 제안이며 사용자 검토 후 구현합니다.
