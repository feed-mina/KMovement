# 실제 생성 모델 기록·검색 텍스트 규칙과 호환성 검증 제안

이번 작업은 기록·소스·기존 벡터 표본을 읽은 분석이며 운영 변경, 모델 로드·추론, Chroma 클라이언트 실행, 재색인·복원·추가 유료 호출은 하지 않았다.

## 확인한 모델 기록과 한계

D:\kride-project\subproject\mlflow.db에서 2026-04-29의 완료된 RAG 실험 두 건을 찾았다. embed_model은 intfloat/multilingual-e5-small, vector_dim은 384, cosine이며 각 실험의 n_sample_pois는 10이다. 이 기록은 해당 시험에서 실제 사용한 모델 기록이지만 장소 40,664개·PDF 3,896개 색인 생성과 묶인 run ID, 모델 revision, 데이터·색인 해시는 없다. 따라서 전체 색인의 실제 생성 모델·revision을 확정하지 않는다.

예전 DB의 네 비어 있지 않은 컬렉션에서 보존된 큐 벡터를 각 32개, 총 128개 검사했다. 모두 FLOAT32·384차원이며 벡터 길이는 약 0.999999928~1.000000115다. 이 결과는 정규화 형식과 일치한다는 증거이지 모델 이름이나 전체 벡터 품질의 증거가 아니다. 세 MLflow DB와 예전 Chroma DB의 읽기 전후 해시는 동일했다.

로컬의 E5-small 캐시 세 곳은 revision 614241f622f53c4eeff9890bdc4f31cfecc418b3을 가진다. 설정은 512 token·대소문자 유지·mean pooling·384차원이다. 캐시의 존재는 검증 후보 확보이며 이 revision이 예전 전체 색인 생성에 사용됐다는 증거는 아니다. 가중치 파일 해시·생성 당시 라이브러리 버전은 아직 기록하지 않았다.

## 텍스트 규칙 비교

| 구분 | 예전 경로 | 현재 공개 경로 |
|---|---|---|
| 장소 문서 | 이름, 카테고리, 주소, 시도, 선택적 아티스트를 공백과 파이프로 연결 | passage: + 이름, 주소, 아티스트 |
| 질문 | 원문·조건 문자열 그대로 전달 | query: + 질문 |
| 정규화 | 생성 및 조회 코드 모두 normalize_embeddings=True | CPU 임베딩 normalize_embeddings=True |
| 계약 기록 | DB에 생성 모델·접두사 계약 없음 | embeddingModel과 e5-prefix-v1 검사 |

예전 장소 문서 40,664개는 저장 메타데이터로 재구성한 옛 builder 형식과 모두 일치한다. 장소·PDF 문서 합계 44,560개는 query:/passage: 접두사가 없다. 예전 TorchServe handler도 입력 문자열에 접두사를 추가하지 않는다. PDF는 실제 저장 문자열을 기준으로 비교하며 원본 PDF를 다시 파싱하지 않는다. 옛 설정은 800자 청크·200자 겹침이고 실제 PDF 문자열 3,896개는 모두 800자 이하다. 문자 수와 모델 token 수는 같지 않다.

모델 발행자의 공식 안내는 검색에서 질문과 문서의 접두사를 구분하고 입력 길이를 512 token으로 제한한다. [E5-small 공식 모델 문서](https://huggingface.co/intfloat/multilingual-e5-small/raw/main/README.md). 이 규칙은 현재 공개 코드와 부합하지만, 접두사가 다른 옛 색인의 실제 검색 품질은 별도 비교가 필요하다.

## 운영 변경 없는 검증 방법 · 제안, 미실행

1. 원본 DB·압축의 해시를 고정하고 읽기 전용으로 취급한다. 검증 후보 모델 revision, 설정·가중치·tokenizer 해시, 라이브러리 버전을 별도 manifest에 남긴다. 자동 다운로드나 운영 설정 변경은 하지 않는다.
2. 기존 큐에 남은 원문·벡터 쌍 128개로 후보 모델 지문을 비교한다. 저장 원문 그대로 처리하고 접두사·공백·대소문자를 임의로 바꾸지 않는다. 계산 결과를 보고서에만 기록하며 DB·색인은 쓰지 않는다.
3. 저장 벡터를 고정하고 질문만 원문/`query:` 두 방식으로 비교한다. 한국어 12·영어 12·일본어 12·근거 없음 4개의 검토된 정답 ID를 준비한다. 부분 표본의 수학적 검색은 전체 40,664개 검색 결과로 확대하지 않는다.
4. 전체 검색 확인이 필요하면 완전한 일회용 복사본과 네트워크 차단·인증정보 없는 CPU 환경을 사용한다. 클라이언트의 스키마 변경이나 큐 재생 가능성을 점검하고 복사본의 변화도 기록한다. 원본·운영 볼륨은 쓰기 가능하게 마운트하지 않는다.
5. 컬렉션 이름·metadata·모델/접두사 guard·공개 출처 조건을 따로 점검한다. 같은 벡터라는 사실이 현재 API 연결 성공을 보장하지 않는다. 옛 자료에 e5-prefix-v1 표시만 덧붙여 검증을 통과시키지 않는다.

수치 기준 제안: 384차원·유한 float32·단위 길이 오차 1e-5 이내, 원 벡터와 후보 벡터의 중앙 cosine 0.9999 이상 및 최소 0.999 이상. 이는 아직 실행하지 않은 제안이며 실행 전에 고정할 기준이다. 통과해도 역사적 생성 모델의 확정이 아니라 표본에서 후보가 수치상 일치한다는 판정이다.

검색 기준은 baseline 대비 Recall@5·nDCG@10, 올바른 ID·지역·출처 및 근거 없음 처리다. 정답 목록과 품질 목표 수치는 아직 준비하지 않았다. E5의 점수 분포와 질문 형식이 달라질 수 있어 예전 distance 0.25 cutoff를 그대로 신뢰하지 않고 다시 평가한다.

최종 판정은 수치 표본 호환성 / 전체 검색 호환성 / 공개 API 계약 호환성을 나눠 기록한다. 원본 해시 보존과 운영·유료 호출 없음이 확인 조건이다. 이번에는 이 검증을 실행하지 않았으며 앱 코드나 운영을 변경하지 않았다.
