## AI 계정과 비밀키 준비

담당: 사용자 · 조건부 본인 작업 / 상태: 서버 키 없음 확인

운영 서버에 AI 연결용 비밀키가 아직 없습니다. 계정이 있는지, 다른 곳에 사용할 수 있는 키가 있는지는 확인하지 않았습니다.

- 공식 AI 서비스의 API Keys 화면을 엽니다. 로그인이나 본인 확인이 나오면 직접 진행합니다.
- 이미 사용할 수 있는 키가 있으면 다시 만들 필요가 없습니다. 새 키는 권한이 있는 계정에서만 만듭니다.
- 키를 어디에 안전하게 넣을지는 도우미가 먼저 확인하게 하세요. 키를 이 대화에 붙여넣지 마세요.

부탁할 요청문:

> 운영 서버의 비밀키 입력 위치와 안전한 등록 방법을 먼저 확인해줘. 키 값은 출력하지 말고, 등록 뒤 연결 가능 여부만 검사해줘. 이번 요청문만으로 실제 등록이나 결제를 진행하지는 마.

완료 증거: 키를 화면에 보여주지 않고 “등록됨”과 “연결 확인됨”을 각각 받습니다.

실패 대응: 로그인·본인 확인은 사용자가 처리합니다. 권한이 없으면 계정 관리자에게 권한을 받아야 합니다. 별도 결제가 필요할 때도 사용자가 결정합니다.

## 비용과 첫 공개 범위 정하기

담당: 사용자 · 결정 / 상태: 제안 · 미적용

서버에는 하루 한도가 설정돼 있지만, AI 사용 단가 두 값은 아직 없습니다. 한도가 있다는 것만으로 준비가 끝난 것은 아닙니다.

- 첫 시험은 하루 합산 최대 금액(사용자와 확정), 한 사람당 하루 10회, 동시에 2건을 제안합니다. 아직 바꾼 설정은 아닙니다.
- 첫 추천 범위는 서울 당일치기 5–10곳, 첫 이용자는 테스트 계정으로 좁히는 방법을 검토하세요.
- 사용할 AI와 단가는 도우미가 조사하고 비교하도록 맡길 수 있습니다.

부탁할 요청문:

> 제안한 비용 한도와 첫 공개 범위가 실제 설정에 어떻게 적용될지 정리해줘. 현재 설정을 읽어 비교하고, 내가 선택하기 전에는 금액이나 공개 범위를 바꾸지 마.

완료 증거: 선택한 한도·사용자 범위와 실제 적용 결과가 같은지 보고받습니다.

실패 대응: 금액이나 공개 범위가 미정이면 도우미는 조사·구현 준비만 진행하고 실제 유료 이용은 열지 않습니다.

## 완료 확인할 때 서비스 로그인

담당: 사용자 · 필요할 때만 / 상태: 실제 화면 검사 예정

42개 로컬 검사는 앞선 작업에서 통과했습니다. 실제 사용자의 로그인 화면과 AI 답변 검사는 아직 남았습니다.

- 이미 서비스에 로그인돼 있으면 다시 로그인할 필요는 없습니다.
- 본인 확인이나 로그인 화면이 나올 때만 직접 처리합니다.
- 로그인 후 질문 전송·중단·다시 질문, 일정과 지도를 실제로 보는 검사는 도우미에게 맡길 수 있습니다.

부탁할 요청문:

> 내가 로그인한 뒤 F13의 첫 답변 시간과 중단·재시도, F12의 일정·지도·출처 일치를 실제 화면에서 확인해줘. 완료 결과와 확인하지 못한 부분을 나눠서 보여줘.

완료 증거: 질문 뒤 답변이 보이고, 중단한 답변이 새 질문에 섞이지 않으며, 일정 장소와 지도 표시가 맞는 화면을 확인합니다.

실패 대응: 실패한 화면과 이유를 보고받습니다. 시험용 응답만 나온 것을 실제 AI 답변 성공으로 보지 않습니다.

## 도우미에게 맡길 작업

F12는 추천할 자료와 AI 연결 준비가 남았고, F13은 서버 연결과 공통 비용 제한이 남았습니다.

- F12: 공식 장소 자료와 위치를 조사하고 추천에 쓸 자료를 준비합니다.
- F13: 로그인한 요청을 AI로 연결하고, 중단·재시도와 비용 제한을 연결합니다.
- 두 기능의 검사·배포·복구 명령은 도우미가 실행할 수 있습니다. 이번에는 보고서만 만듭니다.

부탁할 요청문:

완료 증거: 조사한 출처, 바뀔 기능, 검사 결과, 실제 배포 여부를 따로 받습니다.

실패 대응: 접근이 막힌 부분만 사용자 도움을 요청하게 합니다. 나머지 조사·준비는 계속 맡길 수 있습니다.

부탁할 요청문:

실패 대응: 도구 접근 오류를 사용자의 필수 수동 명령으로 바로 전환하지 말고 공식 연결 또는 정식 권한 요청으로 확인합니다.

## Groq 계정·비밀값 등록 경계

담당: 본인 인증: 사용자 / 절차 준비: Codex / 상태: 운영 키 없음 확인

GROQ_API_KEY 미설정, KRIDE_INTERNAL_TOKEN 설정, 입력·출력 단가 미설정, 하루 한도 설정을 운영 CPU 컨테이너에서 값 비노출 방식으로 확인했습니다. 계정의 기존 키·권한·요금제와 안전한 입력 UI는 미확인입니다.

- 사용자는 Groq API Keys에서 필요한 로그인·본인 인증을 처리합니다. 소유자 또는 developer 권한이 필요합니다.
- Codex가 실제 운영 환경 파일/비밀값 저장 위치와 지속 저장 방식을 조사합니다. 원문 값은 출력하지 않습니다.
- 관리 화면이 있으면 사용자 입력을 안내합니다. 없으면 정확한 대상과 숨김 입력 절차를 먼저 준비합니다. 현재 수동 명령은 제공하지 않습니다.
- 로컬 PowerShell에 환경변수를 설정하는 것만으로 운영 컨테이너에 전달되지는 않습니다.

부탁할 요청문:

> 대상은 현재 Hostinger CPU 서비스입니다. Groq 키 없음은 확인됐고 안전한 입력 경로는 미확인입니다. 서버 비밀값 주입 위치·파일 권한·재생성 시 유지 여부를 읽기 전용으로 조사하세요. 기존 키를 공개하거나 채팅으로 요청하지 말고, 사용자 입력이 필요한 정확한 지점과 값 비노출 검증 절차를 제시하세요.

완료 증거: 입력 위치와 방법, 키 존재 여부, 모델 목록/접속 검사의 성공 여부. 키 자체는 증거에 포함하지 않습니다.

실패 대응: 계정 권한이 없으면 사용자/소유자가 처리합니다. 키가 없어도 코드·회귀 테스트·자료 조사는 진행할 수 있습니다.

부탁할 요청문:

> 현행 Llama 모델의 계정 접근과 단가를 확인하고, 필요하면 공개 단가가 있는 대안을 비교하세요. F12·F13의 모델명·단가·전체 출력 토큰 제한을 한 설정으로 묶는 변경안을 만들고, 비용 예약 장부는 보존하세요. 유료 호출은 합의한 검증 범위 내에서만 진행하도록 구분하세요.

실패 대응: 계정 접근·단가가 미확정이면 생성 비활성을 유지합니다. 취소된 호출을 0원으로 확정하거나 최종 사용량 없는 예약을 즉시 환불하지 않습니다.
