# 격리 파일럿 v2 · 사용자 검수 반영 및 오프라인 환경 준비

현재 단계: 검수 완료 확인 반영 / 독립 실행 파일 복사·해시 고정 완료 / OS 격리 경계 미통과 / 검색 실행 미승인.

## 완료한 것

사용자의 “검수 완료”를 v1 질문120개에 대한 검수 완료 확인으로 기록했다. 수정 요청이 없으므로 질문·정답 ID·관련성·분할은 변경하지 않았다. 검수자는 요청 사용자이며, 별도 외부 검수자의 신원·문항별 수정 기록을 받았다고 주장하지 않는다. 사용자 검수 완료를 다시 요청하지 않는다.

v1은 그대로 보존했다. v2의 questions-reviewed.json에 사용자 검수 상태와 확정 정답 필드명을 기록했다. 후보1,000개·품질 기준은 유지하고 전체1,000개를 대상으로 목적/지역의 숨은 필터 없이 비교한다는 검색 범위를 명확히 했다. 질문의 지역 표현은 순위 단서이며 지역 조건 준수를 증명하지 않는다.

새 준비 폴더: `D:/KMovement/pilot-specs/isolated-poi-v2-20261006-202945`. Python 본체·표준 라이브러리·설치된 전체 site-packages·모델을 별도 물리 파일로 복사했다. 원래 환경을 심볼릭 링크나 하드링크로 연결하지 않았다. 모든 복사 파일에서 원본의 복사 전/후 SHA256과 복사본 SHA256을 대조했다.

고정한 실행 파일 총 33,164개, 1,571,859,809바이트. 그룹별 {"model": 10, "launch-config": 1, "python-base": 2317, "installed-dependencies": 30836}. 자동 생성 가능한 pyc 및 __pycache__를 제외했고, 기본 Python의 site-packages 대신 기존 검증용 환경의 전체 site-packages를 복사했다. 새 launcher 설정1개도 해시에 포함된다.

이것은 **현재 설치된 Windows 실행 파일 전체의 고정본**이다. wheel/sdist 원본을 확보해 재설치 가능한 의존성 lock을 만들었다는 뜻은 아니다. Windows 시스템 DLL·OS 자체는 별도 플랫폼 의존성이다. 설치·다운로드·모델 추론은 하지 않았다.

모델: intfloat/multilingual-e5-small revision 614241f622f53c4eeff9890bdc4f31cfecc418b3. 기존10개 모델 파일 해시와 독립 복사본이 일치한다. 토크나이저·config·가중치가 모두 별도 model 폴더에 있으며 모델은 로드하지 않았다.

## 검증한 실행 경계

복사한 python.exe를 `-I -S -B`와 고정된 python311._pth로 실행해 표준 라이브러리만 사용하는 확인 프로그램을 돌렸다. sys.path가 새 runtime 내부만 가리키고 사용자 site·환경 PYTHONPATH·.pth 자동 초기화가 실행되지 않는 것을 확인했다. 주요 패키지6개의 위치는 find_spec으로만 확인했으며 torch/Chroma/모델을 import하지 않았다.

Python 3.11.15, SQLite 3.53.1, 설치 배포본 123개를 확인했다. 이는 검색 호환성·모델 추론 성공이 아니다. 검사 뒤에도 실행 파일 전체 해시와 기존 v1 파일 해시가 유지됐다.

복사본의 pip check 결과: 통과. 종료 코드 0, 출력 `No broken requirements found.`. 설치 메타데이터의 의존성 선언만 확인하며 모델·네이티브 확장 ABI의 실제 동작 보장이 아니다. 다운로드·추가 설치는 하지 않았다.

환경변수는 SystemRoot/WINDIR, 별도 TEMP/TMP, 새 runtime PATH 및 offline/cache 설정만 전달했다. 인증 환경변수·기존 HOME/USERPROFILE·외부 PYTHONPATH를 상속하지 않았다. 사용자 프로세스 토큰이 다른 파일을 읽을 수 없다는 뜻은 아니다.

## 아직 통과하지 않은 경계

로컬 Docker 컨텍스트는 두 개 모두 named pipe 기반 로컬 엔진이다. desktop-linux와 default 모두 엔진 pipe가 없어 연결되지 않았다. Docker를 시작하거나 Windows 기능·방화벽·시스템 설정을 변경하지 않았다.

이 PC의 System32에서 WindowsSandbox.exe도 발견되지 않았다. 다른 VM 실행 환경은 이번에 확인되지 않았으며 없는 기능을 설치된 것으로 가정하지 않았다.

HF_HUB_OFFLINE/TRANSFORMERS_OFFLINE 설정은 라이브러리의 다운로드를 억제하는 설정이며 OS 네트워크 차단이 아니다. Python sys.path 고정은 import 경로 통제이며 파일 접근 sandbox가 아니다. 네트워크 연결을 시험하거나 원본/운영 경로 접근을 시도하지 않았다.

따라서 OS가 강제하는 외부 파일 읽기/쓰기 제한과 네트워크 차단은 **미확립·미통과**다. 현재 runtime은 Windows용이므로 Linux Docker가 켜지는 것만으로 이 환경을 실행할 수 없다. Linux 환경으로 바꾸면 해당 플랫폼의 패키지·모델·실행 파일을 별도로 고정하고 다시 검사해야 한다.

다음 단계의 안전한 선택은 네트워크가 없는 별도 Windows VM 또는 지원되는 Windows Sandbox에 고정된 입력만 옮기는 것이다. 호스트의 원본·운영·홈 폴더를 공유하지 않고 인증정보를 전달하지 않아야 한다. OS 경계 검사는 보호 대상 원본을 건드리는 대신 테스트용 금지 파일·쓰기 위치·네트워크 차단 설정과 시험 증거로 확인한다. 현재 이 실행 환경은 생성하지 않았다.

## 다음 행동과 중단 이유

이 단계의 실행 경계가 통과하지 않았으므로 파일럿 검색을 시작하지 않는다. 다음 준비 대상은 OS가 강제하는 Windows 격리 환경과 경계 증거다. 이를 통과한 뒤에도 실제 파일럿은 사용자의 별도 실행 승인에서 시작한다. 이번 중단은 자동 승인 거절이 아니라, 사용자가 정한 격리 조건을 아직 충족하지 못했기 때문이다.

사용자가 지금 검수나 터미널 명령을 다시 수행할 필요는 없다. OS 격리 환경 선택·준비가 남았다는 점과 검색 실행 승인이 별개라는 점을 검토하면 된다. 기존 운영 서비스·옛 DB·원본 데이터의 수리/변경·재색인·배포는 하지 않았다.
