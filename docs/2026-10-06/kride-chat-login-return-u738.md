# KRIDE 채팅 로그인 연결 후속 수정·배포

2026-10-06. 기존 UI·텍스트 채팅 배포를 재확인하고 카카오 로그인 후 선택한 채팅으로 돌아오는 연결을 보완했다.

## 문제와 수정

영어·일본어 화면의 로그인 링크는 복귀 주소를 전달하지만 카카오 버튼은 이를 저장하지 않았다. 기존 인증 콜백은 My/Main으로 보내므로 사용자가 선택한 대화를 다시 찾아야 했다.

카카오 이동 직전에 같은 탭의 복귀 경로를 기록하고, `/api/auth/me`로 준비된 계정이 확인된 뒤에 원래 화면으로 돌아오도록 수정했다. 내부 view 경로만 허용하며 경로 정규화·10분 만료·한 번 소비를 적용했다. 회원 정보 입력이 필요한 계정은 기존 흐름을 유지한다. 이메일 로그인과 로그아웃은 이전 복귀 힌트를 지운다. 힌트에는 계정 정보와 인증 토큰이 없다.

## 배포·검증

- [PR #271](https://github.com/feed-mina/KMovement/pull/271) 병합 소스 `7d334d94a36cac70e1680812ced0334002247756`.
- 운영 웹 이미지 `ghcr.io/feed-mina/kmovement-web@sha256:1de8fe334340f27e9a14912ea4af62904249330f01783dc287c160a028188346`. 실행 이미지·OCI 소스 버전과 healthy 확인, 기존 볼륨 보존. CPU·Spring·DB·비용 장부와 공급자 설정을 변경하지 않았다.
- 변경 관련 로그인 복귀·계정 화면·언어 화면 검사 18개, 소스 타입 검사 통과. PR 자동 검사 6개 통과, Supabase preview skipped. 웹 제작 워크플로 37418121068 성공.
- 로컬 브라우저에서 영어·일본어 각각 390·1440px의 로그인→복귀 4개 조합 통과. 복귀 정보 삭제·가로 넘침·페이지 오류 확인. 인증 및 OAuth는 검증용 응답이며 실제 계정 로그인이나 공급자 호출이 아니다.
- 공개 운영 7개 페이지 × 390·1440px = 14개 검사 통과. HTTP 200, 페이지 오류·가로 넘침 없음. 실제 로그인한 마이페이지의 저장 동작까지 확인한 결과로 확대하지 않는다.
- 운영 카카오 로그인 시작 302 및 현재 사이트의 콜백 주소 확인. 채팅 정상 출처 비로그인 요청 401, 외부 출처 요청 403. 실제 카카오 인증 완료는 미확인.
- 이번 작업에서 유료 공급자 추가 호출 없음. 기존의 내부 서버 첫 응답 측정은 로그인 브라우저의 이번 측정으로 재사용하지 않았다.
- 독립 HTML 3개: 내부 연결·자원 검사와 390·768·1440px 노드 5개, 탭, Enter·Space·Home·End 조작 검사 통과.

## 남은 확인과 사용자 행동

사용자가 직접 터미널을 실행할 일은 없다. 운영 사이트를 새로고침하고 영어 또는 일본어에서 로그인한 뒤 같은 언어의 입력창으로 돌아오는지 확인한다. 실제 브라우저 제어 도구가 로컬 경로 오류로 연결되지 않아 카카오 인증 완료·첫 답변 표시·저장·삭제 동작은 실제 사용자 확인이 남는다. 비밀번호·쿠키·키 값을 전달할 필요가 없다.

이전 보고서의 음성 기능, F12 출처 있는 추천 자료, 공개 상품 후보 데이터 준비는 별도 후속 항목이다. 이번 보완은 UI·텍스트 채팅의 로그인 연결에 집중했다.
