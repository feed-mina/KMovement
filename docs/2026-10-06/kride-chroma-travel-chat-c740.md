# KRIDE Chroma 복구 및 여행봇 모드 수정·배포

2026-10-06. 원본 후보·검색 색인·여행봇 경로를 수정하고 운영 웹·CPU 서비스에 반영했다. 실제 로그인 브라우저 확인은 별도로 남아 있다.

## 원인과 조치

Chroma heartbeat·컬렉션 조회는 정상이나 공개 API 첫 300건에 출처 URL이 없어 유효 후보 0건이었다. 일정 생성은 검색 전에 empty_candidates로 종료됐다. 빈 DB 초기화나 같은 빈 원본의 재색인은 해결책이 아니었다.

서울문화포털의 이름·주소와 같은 페이지의 markerLocations 좌표를 확인한 일반 공개 장소 3곳(서울역사박물관, 남산골한옥마을, N서울타워)을 별도 버전 원본으로 공급했다. 기존 DB 행을 수정하거나 출처·아티스트 연관을 임의로 만들지 않았다. 원본은 승인·기한·좌표·공식 URL을 매번 검사하며, 기한이 지난 자료나 철회 자료는 옛 색인에 남아도 제공하지 않는다. 검토 기한은 2026-11-05다.

기존 Chroma를 백업하고 같은 multilingual-e5-small CPU 모델·e5-prefix-v1 계약으로 실제 384차원 벡터를 생성해 0→3건 추가했다. 삭제 0건. 세 장소의 실제 이름 검색 모두 해당 ID가 첫 결과였다. 빈 원본으로 갱신하는 명령은 거부한다. CPU는 시작할 때 모델을 미리 읽은 뒤 준비 상태를 제공한다.

여행봇 QA는 실제 검색 자료와 구조화된 출처를 사용하는 CPU 스트림으로, 추천·일정은 새 인증 프록시로 연결했다. 미설정 legacy non-stream API 의존을 없앴다. 로그인한 서버 확인 ID만 전달하고 기존 시험 계정·공유 비용 장부·사용자 하루 10회·동시 2건을 유지한다. 추천 조회도 횟수에 포함한다. 자동 유료 재시도는 없으며 중단 예약은 유지된다.

더보기의 여행봇 진입, 로그인 안내, 중단·직접 재시도·종료를 제공한다. 작동하지 않는 음성·적용 버튼을 제거했다. 일정과 마커의 출처를 유지하고 저녁 장소 표시를 보완했다. 범위 슬라이더의 배열 예산을 서버 객체로 맞췄다. 브라우저 캡처에서 흰 배경에 흰 글자가 묻히고 카드가 압축되는 문제를 발견해 대비와 배치를 추가 수정했다.

## 사용자 행동과 남은 확인

터미널 입력이나 키 재등록은 필요 없다. 사이트 새로고침 → 더보기 → 여행봇 → 로그인 후 서울 당일치기를 질문한다. 실제 로그인 브라우저 조작 도구가 os error 3으로 연결되지 않아 본인 계정의 첫 표시 시간·지도 조작·중단·재시도·종료는 사용자 확인이 남았다. 비밀번호·쿠키·키 값을 보낼 필요는 없다.
