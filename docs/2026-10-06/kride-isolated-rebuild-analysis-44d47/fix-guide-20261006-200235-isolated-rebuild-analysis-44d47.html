# 원본 40,664개 보존과 새 격리 검색 DB 재구축 검토

현재 단계: 분석 완료·실험 설계 제안. 2026-10-06. 이번에는 JSON 및 기존 격리 복사본의 SQLite 스키마만 읽었다. 모델 실행, 임베딩, Chroma 클라이언트, 새 색인 생성, 운영 접속·변경·배포는 하지 않았다.

## 결론

예전 Chroma를 수리해 운영에 넣기보다, 보존된 논리 원본으로 새 격리 검색 DB를 만드는 방향을 검토하는 것이 타당하다. 독립 JSON의 장소 40,664개와 고유 ID가 남아 있고, 이전 전량 대조에서 예전 SQLite의 ID·명칭·주소·분류·좌표와 일치했다. 이번에도 해당 원본 해시가 유지됨을 확인했다. 옛 내부 색인을 복구하지 않고 새 검색 구조를 평가할 근거가 있다.

다만 곧바로 40,664개를 재색인하거나 운영 적격 자료로 취급하지 않는다. 다음 실행 후보는 원본 목록·결측 판정 고정 → 검수된 다국어 질문 준비 → 500~1,000개 소규모 격리 색인 비교 → 통과 후 전체 재구축이다. 표본 크기는 제안이며 아직 선정하지 않았다.

## 2. 예전 DB 오류의 더 정확한 해석

이전 SQLite3.53.1 검사에서 `malformed inverted index for FTS5 table main.embedding_fulltext_search`가 기록되었다. 이번에는 이 검사를 재실행하거나 수리하지 않았다. 전문 검색 색인의 이상 또는 버전 호환 원인은 미확정이다. HNSW 벡터 색인은 열지 않았으므로 손상이 증명됐다고 표현하지 않는다.

새로 읽은 스키마에서 `segments.collection`의 외래키 대상은 단수 `collection(id)`인데 실제 테이블은 복수 `collections`였다. segment10개를 실제 `collections.id`와 대조한 미연결 수는 0이다. 따라서 이전 외래키 실패10건을 장소10개 또는 실제 collection 연결10개의 유실로 해석하면 안 된다. 참조 대상 이름 불일치를 확인했으며 수정은 하지 않았다.

SQLite의 무결성 검사와 외래키 검사는 별개다. [SQLite 공식 PRAGMA 문서](https://www.sqlite.org/pragma.html#pragma_integrity_check). 이 공식 설명은 검사 구분의 근거이며 프로젝트 오류 원인을 대신 증명하지 않는다.

## 4. 128쌍 결과가 뜻하는 것

모델128개가 아니라 **후보 모델1개의 문서·벡터128쌍**이다. 장소96쌍과 PDF32쌍에서 후보 `intfloat/multilingual-e5-small`, revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`의 수치가 기존 저장 표본과 일치했다. 최대 norm 오차1.1921e-7, cosine 중앙1.0·최소0.9999998808이다. 기준 norm≤1e-5·중앙≥0.9999·최소≥0.999를 통과한 이전 결과이며 이번 재실행은 없다.

전체 생성 모델의 역사적 revision, 모든 저장 벡터, 검색 품질, 공개 적격성은 증명하지 않는다. 실행 준비에는 모델 파일10개 해시·tokenizer·config·pooling·정규화·최대 길이·라이브러리를 고정한다. 이전 실험 버전은 numpy2.4.6, torch2.14.1+cpu, sentence-transformers6.1.0, transformers5.18.0, tokenizers0.23.2, chromadb1.5.9, SQLite3.53.1이며 과거 생성 환경으로 단정하지 않는다.

## 5. 영어·일본어 문제를 먼저 분리하는 실험안

이전에는 목적별 저장 표본32개 내에서 이름 중심 질문을 언어별12개, 근거없는 질문4개로 평가했다. Recall@5는 한국어1.0·영어0.5833·일본어0.6667이었다. 원문 질문과 `query:` 질문 모두 같은 Recall이었다. 독립 검수된 일반 여행 질문이나 전체40,664개 검색 결과가 아니다. 문서까지 `passage:`로 새로 만든 조합은 아직 시험하지 않았다.

E5 공식 지침은 비영어 검색에도 문서와 질문의 역할 접두사를 권장한다. 따라서 질문 접두사만의 실패로 다국어 모델 전체가 부적합하다고 결론 내리지 않는다. [E5 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md).

| 변형 | 문서 | 질문 | 분리할 효과 |
|---|---|---|---|
| A | 보존된 옛 문서 형식 | 원문 | 새 파일럿 내 재현 baseline |
| B | A와 동일 | query: | 질문 형식만 변경 |
| C | B 문서 앞 passage: 추가 | B와 동일 | 문서 형식만 변경 |
| D, 필요할 때만 | C 기반 검증된 다국어 별칭 등 한 변경 | C와 동일 | 텍스트 보강 또는 별도 어휘 검색 결합을 한 번씩 비교 |

같은 후보 ID·문서 집합·질문·정답·순위를 유지한다. 모델·본문 필드·질문 형식·ranker를 한꺼번에 바꾸지 않는다. A/B는 동일 문서 벡터를 재사용하고 B/C만 새 문서 임베딩 차이를 비교한다. old32개 결과와 새500~1,000개 결과는 직접 같은 모집단 점수로 취급하지 않는다.

새 질문셋 제안: 총120개, 언어별 긍정30·근거없음10. 개발60/보류평가60에 언어별 긍정15·부정5씩 배분한다. 아직 질문·정답·절대 목표의 독립 검수를 완료하지 않았다. 이름 번역뿐 아니라 의도 검색·동명이 장소·지역 및 취향·확인되지 않은 가격/아티스트 주장·답 없는 질문을 포함한다. 장소 단위 중복과 번역 누출을 점검하고 사람이 관련성 등급·정답 ID를 검수한다. 보류평가를 보고 문구나 기준을 조정하지 않는다.

제안 품질 목표는 언어별 Recall@5≥0.80·nDCG@10≥0.70, baseline 대비 하락≤0.02다. 표본 수와 불확실성을 함께 보고하고 실행 전에 기준을 확정한다. 근거없는 답변 승인0건을 목표로 하되, 가까운 검색 후보 반환과 답변 승인 여부를 구분하고 정상 질문의 과도한 거절률도 기록한다. 이전 부정4개는 cosine 약0.78~0.84의 후보가 나왔으므로 단일 거리 기준을 사실 확인으로 사용하지 않는다.

## 6. 전량 구축은 소규모 검증 뒤 별도 실행

새 Chroma는 기존 경로·컬렉션이 존재하면 중단하도록 만들고 운영 호스트·볼륨·자격증명 접근을 차단한다. `documents`만 넣어 자동 임베딩이 선택되지 않도록 모델로 계산한 embeddings·IDs·문서·metadata를 명시한다. 중복 ID는 삽입 시 무시될 수 있으므로 요청 수만으로 완료 판정하지 않고 ID 집합·개수·필드 해시·차원을 대조한다. [Chroma 공식 데이터 추가 문서](https://docs.trychroma.com/docs/collections/add-data).

전체 구축 후에는 닫기/재열기 지속성, 유한 float32·384차원·norm, 논리 ID 재대조, SQLite·FK 검사, migration/큐 재생 기록을 확인한다. 이상 시 해당 격리 복사본에서 중단한다. HNSW 근사검색과 같은 벡터의 정확검색 비교 목표 Recall@10≥0.99는 별도 제안이다. ANN 근사 정확도와 사용자가 원하는 장소를 찾는 정답 품질을 혼동하지 않는다. 전체 후보가 늘어난 조건에서 다국어 품질을 다시 평가한다.

40,664×384×4의 벡터 원시 저장량만 62,459,904바이트(약59.57MiB)다. 문서·SQLite·색인·모델·작업 복사본은 추가되므로 이 수치를 필요 디스크/메모리나 처리 시간으로 제시하지 않는다. 파일럿에서 CPU 처리율·최대 메모리·디스크 증가를 측정한 뒤 용량과 시간을 계획한다.

## 7. 운영 후보 판정은 별도

새 검색 DB가 통과해도 출처 URL·좌표·지역·가격 및 연예인 관계 근거를 갖춘 공개 적격 자료만 서비스에 연결한다. 링크 유효성·원출처 권한·확인일·좌표 일치·불명확할 때 보류를 확인한다. 계약명만 붙여 guard를 통과시키지 않는다.

현재 코드 `src/api/public_search.py`는 `kride_public_poi_v1`을 사용하며 `index_catalog`에서 오래된 ID를 삭제하는 경로가 있다. 따라서 연구 자료를 이 함수나 운영 컬렉션으로 밀어 넣지 않는다. 별도 offline builder와 별도 컬렉션, ID 매핑 및 논리 export가 필요하다. 이는 설계안이며 코드 수정하지 않았다.

`src/api/public_itinerary.py`의 서울·당일치기 제한은 별도 입력 규칙이다. 새 DB만 만들어도 다지역·여러 일정·여행 예산·아티스트 순위 반영이 자동으로 복원되지 않는다. 현재 예산 필드는 받아도 LLM 조건 전달과 비용 준수 검증이 별도이며 제공자 사용료 제한과 여행 예산은 다르다.

운영 후보가 되려면 검색 품질, 공개 출처 계약, 일정·지도·출처 ID 일치, 지역/예산/관계 조건, 로그인 후 실제 첫 응답 시간·종료·재시도, 기존 하루1달러·사용자10회·동시2건 제한을 각각 확인한다. 운영 전환은 별도 승인된 단계에서 기존 버전으로 되돌릴 수 있는 경로를 준비해 수행한다. 이번 보고서는 전환 승인이나 전국 지원 완료가 아니다.
