# 내 목록·내 영상 P1~P5 구현

공통 메뉴에서 내 목록과 개인 영상을 오가고, 로그인·새로고침·뒤로 가기 후에도 영상 보기 방식·페이지·선택 작업을 복원하도록 구현했다. 기존 PostgreSQL·SQLite·사진·영상 파일과 소유권 검사는 유지한다. 이 문서는 PR의 구현 상태이며 운영 배포 결과가 아니다.

| 단계 | 구현 | 확인 지점 |
|---|---|---|
| P1 공통 이동 | 마이페이지·내 목록·내 영상에 `PersonalLibraryNav`. 내 목록 종류·페이지를 영상의 제한된 `returnTo`로 보존 | 링크와 `aria-current`, 메뉴 이동만으로 생성·삭제·저장 요청 없음 |
| P2 로그인 복귀 | 정확한 `/travel/video`만 추가 허용. 보기 방식·페이지·UUID·제한된 목록 복귀값만 유지. 이메일·OAuth 복귀와 추가 회원 정보 흐름 유지 | 외부·중첩 임의 경로·owner·토큰 제거. API 401이면 클라이언트의 만료 세션을 비우고 로그인 안내 |
| P3 이력 상태 | `usePrivateVideoHistory`에서 조회 중·성공·빈 결과·401·503·기타 실패 분리. 계정·페이지별 요청 취소와 결과 키 검사 | 계정 전환 시 이전 작업·사진·미리보기·코스 정보 숨김. 재조회는 GET만 실행 |
| P4 주소 복원 | `view=create/history`, `page=1..9999`, 정상 UUID `job` 정규화. 선택할 때 서버 상세 GET으로 재검증 | 주소만으로 자동 생성·재시도 없음. 404는 작업 없음, 완료 영상은 보호된 같은 출처 재생 경로 사용 |
| P5 접근성·활성 상태 | 링크·키보드 초점·상태 알림·44px 동작 영역·모바일 배치. 전역 마이 메뉴에서 개인 영상 활성 표시 | 공개 플래그가 꺼져 있으면 영상 메뉴 숨김·직접 진입 안내. 서버 503은 준비 안내, 내 목록은 독립 사용 |

사진·작업 생성은 사용자가 버튼을 누를 때만 한다. 실패한 작업 재시도도 명시적 요청만 허용하며 원작업 번호를 사용한다. 이력 API에는 총 건수가 없으므로 전체 영상 개수는 표시하지 않는다. SQLite 생성 시각은 UTC로 해석한 뒤 한국 시간으로 표시한다.

코스 임시 선택에는 로그인 계정 식별자도 붙여 다른 계정의 장소명을 재사용하지 않는다. 이전 형식의 임시 코스 선택은 다시 코스 화면에서 연결해야 한다. 이미 SQLite에 저장된 `trip_json`·영상 이력은 바꾸지 않는다.

## 배경 제어 UI

사이트의 공통 `PastelBackdrop`에서 ‘배경 움직임 멈춤/재생’ 버튼과 문구·전용 CSS를 제거했다. 버튼 없이 장식 효과가 계속 반복되지 않도록 배경 애니메이션은 4초 후 끝난다. 운영체제의 동작 줄이기, 화면 밖·숨겨진 탭의 중단 처리는 유지한다. 일반 버튼의 클릭·키보드 동작에는 영향이 없다.

## 활성화 조건

- 공개 메뉴·화면은 빌드 시 `NEXT_PUBLIC_PHOTO_VIDEO_ENABLED=true`일 때 열린다. Dockerfile에 같은 이름의 빌드 인자를 추가했으며 기본값은 `false`다.
- 서버 API는 별도로 `PHOTO_VIDEO_ENABLED=true`, 내부 서비스 주소·키·인증 서버·허용 출처가 준비돼야 한다. 공개 플래그가 켜졌다는 이유로 서버 준비 완료로 판정하지 않는다.
- 코스 연결에는 기존 코스 API·서명 설정·허용 계정이 추가로 필요하다. 새 RunPod 작업이나 Cloudinary 업로드를 활성화하지 않는다.
- 기존 NetworkOnly 및 `private, no-store` 정책을 유지했다. 새 서비스 워커 경로·DB 스키마·데이터 이전은 없다.

## 검증

검증 결과는 PR 게시 전에 아래에 기록한다. 로컬 모형 시험은 실제 운영 로그인·사용자 영상 재생 성공과 구분한다.

- 변경 범위의 Jest 11개 묶음, 총 108개 시험 통과. 로그인 경계 보강 후 로그인 시험 29개를 다시 확인했다.
- 로컬 의존성 일부가 불완전해 잠금 파일의 캐시와 기존 동일 버전 패키지를 사용했다. 별도 검증 설정에서 Next Link는 앵커, Next Script는 비실행 대역으로 바꾸고 SWC 자동 JSX·허용된 캐시 경로를 지정했다. 실제 Next 라우터의 브라우저 통합 검증을 대신하지 않는다.
- 주소 검증 계약 직접 검사 16개 통과. 생성·이력의 실제 React 컴포넌트에 설명용 응답을 넣은 정적 화면 4종(1440px·390px)을 렌더링해 가로 넘침이 없음을 확인했다.
- `git diff --check` 통과. 앱·컴포넌트·라이브러리에서 배경 제어 문구·전용 CSS 이름이 남지 않았음을 확인했다.
- 전체 타입 검사·실제 Next 프로덕션 빌드는 로컬 의존성 누락 때문에 최종 확인을 CI에 남겼다. 새 CI는 동일 변경 범위의 Jest와 전체 타입 검사·빌드·격리된 개인 영상 HTTP 시험을 실행한다.
- 실제 운영 로그인·사진 업로드·서버 플래그 변경·새 영상 생성·배포는 수행하지 않았다.

## 적용 후 확인·되돌리기

리뷰·병합·기존 배포 절차 후 비로그인 이력 주소 → 로그인 → 같은 페이지·작업 복귀, 본인 영상 재생, 다른 계정 작업 404, 내 목록 종류·페이지 복귀를 확인한다. 기능을 중지할 때는 공개 빌드 플래그와 서버 플래그의 적용 시점을 구분한다. UI 변경을 되돌릴 때 이 PR의 코드 변경을 되돌리고 기존 SQLite·PostgreSQL·사진·MP4를 삭제하지 않는다.
