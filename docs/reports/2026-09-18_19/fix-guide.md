## 4. 수정 또는 확인 방법

1. 모의 fetch로 정상 일정·빈 일정·통신 실패를 분리해 확인합니다.
2. 코드와 기대 결과가 다를 때에만 해당 분기를 수정합니다.
3. 추천 서버를 호출하는 검증은 별도 실행 환경에서 기록합니다.

## 5. 완료 기준

- [ ] 정상 일정은 data와 markers가 채워지고 isLoading이 false가 됩니다.
- [ ] 통신 실패 후 성공은 총 두 번 요청하고, 빈 일정은 오류 안내가 나옵니다.
- [ ] FOCUS가 아니거나 조건이 없으면 요청이 없습니다.

## 6. 검증 방법과 제출할 근거

훅 테스트에서 요청 횟수와 마지막 상태를 기록합니다. 실제 서버 테스트는 요청 조건, 응답 상태, 화면 안내를 함께 보관합니다. 이번에 실행한 결과로 기재하지 않습니다.

실행 결과·캡처·응답 본문 중 완료 기준에 해당하는 근거를 남깁니다. 미실행 항목은 완료로 표시하지 않습니다.
