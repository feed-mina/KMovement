## 2. 익숙한 상황에 빗대어 보기

여행 안내소에 안내서를 붙인 작업입니다. 안내서에는 접수 창구, 추천 담당자, 지도 담당자의 역할이 정리돼 있습니다. 안내서를 새로 붙였다는 사실만으로 추천 서버의 현재 영업 상태가 확인된 것은 아닙니다.

이 비유는 역할을 이해하기 위한 설명입니다. 실제 저장·승인·실행 조건은 코드 인수인계 보고서를 기준으로 확인합니다.

## 3. 서로 어떻게 연결되는가

기간·아티스트·지역을 고른 값은 추천 요청의 조건이 되고, 응답의 일정과 마커가 화면을 구성합니다. 이번 문서는 이 연결을 설명합니다. 네트워크 재시도와 빈 추천 결과는 서로 다른 분기입니다.

## 4. 직접 확인하는 순서

1. 기존 KMovement 유지보수 문서를 엽니다. 성공 기준: 목차에서 필요한 화면을 찾을 수 있습니다.
2. 추천 오류를 보려면 아래 코드 인수인계에서 useKrideItinerary를 엽니다. 성공 기준: 요청을 생략하는 조건과 한 번 재시도하는 조건을 구분합니다.
3. 실제 동작 확인은 준비된 로컬 환경에서 합니다. 서버 연결 오류가 나면 화면 코드와 추천 서버 주소를 차례로 확인합니다.
