# 아티스트·장소 출처 감사: 권장안 적용 결과

작성일: 2026-10-25 / 기준 소스: 38b056177f645d16d54f3bf7028a58ae808055f5

**기존 명단 전체를 유지하며 관계 후보 631개를 원문 행까지 추적하도록 정리했고, 근거가 없는 아티스트 연결은 맞춤 추천의 근거로 사용하지 않도록 수정했다.**

## 확정한 기준

사용자의 “artist-place-data-lineage-audit 권장값으로 조사·수정” 요청에 따라 보고서 2의 권장안을 적용했다.

- 조사 범위: 현재 서비스 등록 목록 전체. CSV에만 있는 대상은 편입 후보로 분리.
- 크리에이터·채널: 삭제하지 않고 유형을 구분하여 유지.
- 미확인 관계: 조사 후보로 보관하고 아티스트 맞춤 추천에서 제외.
- 유형·별칭은 조사용 잠정 분류다. 활동 상태·소속사·그룹 구성원의 최신 사실을 확정한 명부가 아니다.
- 2팀은 조사 방법을 검증할 표본이다. 전체 조사 대상 48개를 2팀으로 축소하지 않았다.
- 같은 DB 안에 새 검증 표를 만들자는 보고서 3의 제안은 별도 구조 결정이다. 이번에 운영 DB를 생성·삭제·전환하지 않았다.

## 실제 수정한 코드

1. public 검색 목록: 예전 API의 artist 문자열과 자동 승인 값을 아티스트 관계 증거로 사용하지 않는다. 일반 장소는 artist 빈값·artistRelationStatus=unverified·personalizedEligible=false로 전달한다. 원본 DB 행은 바꾸지 않는다.
2. 시간 의미: API를 가져온 시간은 fetchedAt으로 기록한다. 검토하지 않은 자료에 verifiedAt을 새로 만들지 않는다. 독립 검토된 기존 curated 장소의 검증 시각은 유지한다.
3. 옛 CSV 로더: 이름+주소로 찾지 못했을 때 이름만으로 다른 지점을 재사용하던 처리를 제거했다. 이 로더는 여전히 옛 20개 아티스트 스키마 전용이며 Spring 운영 DB 적재에 사용하지 않는다.
4. 성지 SQL 생성기: 새 결과는 PENDING으로만 생성한다. 기존 Flyway SQL·이미 존재하는 파일을 덮어쓰지 못하도록 막고, DELETE를 제거해 기존 장소를 보존한다. 새 SQL은 별도 경로를 지정해야 하며 자동 실행하지 않는다.
5. 전수 조사 도구: 전체 명단별 0개 행도 남기고, 원문 해시·행 번호·별칭 후보·지점 주소·미확인 상태를 함께 기록한다.
6. GitHub 검사: 조사 산출물 재생성 일치와 정책 회귀 시험을 검사한다. main 반영 후에는 별도 읽기 전용 작업으로 운영 명단과 집계를 확보한다.

이 변경은 전체 성지 탐색 화면의 기존 승인 자료를 일괄 삭제하거나 숨기는 작업이 아니다. 미확인 관계의 맞춤 추천 사용을 제한하는 CPU 검색 경로와 앞으로의 적재 도구를 수정한다. 현재 public AI 코스는 계속 일반 장소 코스이며, 실제 아티스트 맞춤 생성 기능을 새로 완성했다고 표시하지 않는다.

## 운영 실측과 배포

작성 시점에 로컬 DNS와 웹 조회 도구로 운영 API에 연결하지 못했다. 따라서 저장된 CSV 산출물의 48은 소스 예상치다.

새 GitHub workflow의 live-snapshot 작업은 main push/수동 실행에서만 배포용 SSH로 연결한다. PostgreSQL에서 READ ONLY + REPEATABLE READ 트랜잭션으로 승인 목록·전체 수·성지 표별 개수만 조회한다. 계정·환경변수·비밀번호·사용자 코스는 출력하지 않는다. 결과는 7일 보관 artifact에 저장하며 실행 로그에는 공개 승인 명단과 집계 JSON만 남긴다. 이 작업의 성공 여부와 실제 수는 실행 결과를 보고 확인해야 한다. PR에서는 운영 연결을 실행하지 않는다.

main 자동 배포는 웹 전용이다. 이 PR의 CPU Python 수정은 main 반영만으로 운영 CPU 컨테이너에 배포되지 않는다. CPU 이미지 검증·발행·교체가 끝나기 전에는 운영에서 관계 차단이 적용됐다고 주장할 수 없다. 수집 로더와 생성기는 자동 실행하지 않는다.

## 정합성 70%와 다음 작업

631개는 별칭 제안 단계라 전체 관계 정확도 점수를 산출하지 않는다. 미확인 631개를 오류 631개나 정확도 0%로 표현하지 않는다. 신뢰할 원문을 확인한 다음 V(검증), I(오류), U(미확인)를 판정하고 검증 확보율과 판정 자료의 사실 정합률을 따로 계산해야 한다.

다음 순서: 운영 명단 실측 → 잠정 별칭/유형 확인 → 전체 후보의 공식 관계·정확한 지점 확인 → 운영자 안내에서 최신 시간·예약·방문 가능 상태 확인 → 통과 행만 맞춤 추천 후보로 승격. 원본 CSV 3종 복구와 기존 SQL·그래프·인덱스 대조도 남아 있다.
