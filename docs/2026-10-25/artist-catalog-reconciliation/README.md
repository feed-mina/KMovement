# 기존 명단 유지와 새 92개 이름 대조

2026-10-25 / 실제 운영 DB 수정 없음

**아이유·차은우를 포함한 기존 소스 명단 48개를 유지하고, 새 92개를 추가한 통합 계획 명단 140개를 작성했다.**

92개는 기존 명단을 대체하는 전체 명단이 아니다. 새로 더할 이름 후보다. 사용자 지시대로 2:00 AM, 2:00 PM, 기분 째니는 날, 한끼줍쇼, 이사배 5개는 새 92개 바깥의 보류 명단으로 유지한다.

## 이번 실제 분류

| 기준 | 기존 유지 | 새 입력 | 중복 | 신규 후보 | 판단 보류 | 통합 계획 |
|---|---:|---:|---:|---:|---:|---:|
| 소스 명단 대조 | 48 | 92 | 0 | 92 | 0 | 140 |

이 수는 **현재 운영 DB 실측 결과가 아니다.** 실제 번호는 조회하지 못했으므로 빈칸으로 남기고 새 번호를 추측하거나 할당하지 않았다. 신규 후보는 이름상 기존 소스 명단에 없는 항목이라는 뜻이다. 운영 명단에 이미 등록됐거나 다른 이름을 쓰는 항목은 실측 후 중복/보류로 달라질 수 있다. 별도 제외한 5개를 새 92개의 판단 보류 0개에 섞지 않는다.

## 기존 항목과 번호 보존

- 아이유(IU), 차은우뿐 아니라 기존 48개를 모두 유지한다.
- 기존 slug는 보존하며 표의 행 순서를 서비스 번호로 쓰지 않는다.
- 실제 전체 명단을 입력하면 원래 숫자 ID를 그대로 결과에 기록한다. 새 항목에는 ID를 발급하지 않는다.
- 같은 이름으로 여러 기존 ID가 잡히면 판단 보류로 남긴다. 기존 두 ID를 자동 병합하거나 삭제하지 않는다.
- 미승인 기존 항목도 중복 검토에 포함하고 승인 상태를 자동으로 바꾸지 않는다.
- 같은 자료를 다시 대조하거나 명시적으로 같은 별칭을 쓰는 이름을 입력하면 기존/동일 신규 후보를 참조한다.
- 그룹·멤버·채널·출연 관계는 이름 매칭에 사용하지 않는다. 장소 관계를 만들거나 상속하는 코드 자체가 없으며 추가된 장소 관계는 0개다.
- IVE와 장원영은 별개 대상이다. 그룹의 장소를 개인에게 넘기지 않는다.

## 재현과 실제 명단 대조

```powershell
python scripts/reconcile_artist_catalog.py --output work/catalog-reconciliation
python -m unittest discover -s tests -p test_artist_catalog_reconciliation.py -v
```

실제 전체 artist 명단 JSON을 확보한 뒤 --master-json 경로를 추가한다. 승인된 공개 목록만 담은 API 응답은 미승인 기존 항목을 누락하므로 사용하지 않는다. 입력은 masterScope=all_artists, allArtistCount와 data.totalCount가 전체 items 길이와 일치해야 하며 각 행에 실제 id, slug, 승인 상태가 있어야 한다.

입력에서 원래 유지해야 할 대상이 누락되면 중단한다. 이름/별칭이 여러 대상에 겹치거나 그룹·개인 유형이 충돌하면 보류한다. 이름 일치도 정체성 검토가 필요한 연결 후보이므로 실제 등록·병합은 이 도구가 실행하지 않는다. 장소 근거가 확인됐다는 의미도 아니다.

## 검증 범위

16개 단위 시험: 아이유·차은우 유지, 명시 별칭 중복, 실제 숫자 ID 보존, 미승인 상태 보존, 여러 ID 충돌 보류, 새 입력 중복, 5개 제외, 그룹·개인 분리, 장소 상속 요청 거부, 전체 명단 누락·잘못된 ID·별칭 형식 거부, 집계 재현.

운영 DB 조회, 사이트 등록, 기존 ID의 실서버 대조, 관계 전수 검증, 서버·검색 운영 전환은 아직 실행하지 않았다.
