KMovement Hostinger 웹 전용 배포 준비

결론: PR #246은 web+Caddy만 배포하도록 경계를 고정했고, 검토에서 발견한 main SHA 오표기 위험과 digest 미강제 문제를 보완했다. 실제 Hostinger·HTTPS·주소검색 검증은 사용자 승인 전 실행하지 않았다.

Before / After
Before · 검토 전
기록한 main과 실제 빌드가 다를 수 있음
런북은 origin/main SHA를 변수에 담았지만 현재 HEAD가 그 SHA인지 확인하지 않았다. Compose 이미지도 tag-only 값을 자동으로 거부하지 않았다.
After · 구현됨
HEAD 일치와 digest 형식을 gate로 강제
빌드 전 HEAD=origin/main을 검사한다. CI는 web·Caddy 이미지가 각각 64자리 sha256 digest이고 web 3000이 공개되지 않았는지 확인한다.
현재 실제 화면
없음. Hostinger에는 배포하지 않았고 운영 DNS도 바꾸지 않았다.
예상 화면 · 미구현
임시 HTTPS의 /holy/submit에서 주소 선택 후 좌표와 Kakao 마커가 함께 바뀐다. 저장 제출은 검사하지 않는다.
